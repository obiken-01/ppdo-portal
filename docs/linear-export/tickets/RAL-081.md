# RAL-81 — Permissions: Budget Planning + Config permission flags and office assignment

> 🌿 **Working branch:** `release/1.1.0` — all v1.1 work branches off `release/1.1.0` and PRs target `release/1.1.0` (not `main`).

## Overview

Add new permission flags for the Budget Planning module and the Configuration section, plus full support for **non-PPDO office users**. Follows the existing PermissionGroup + per-user override pattern. **Implement after the DB tables ticket ([RAL-67](<https://linear.app/ralphoksiprojects/issue/RAL-67/db-budget-planning-schema-v2-ldip-aip-wfp-config-tables>)).**

> **Authoritative reference:** `docs/v1.1/User_Roles_Permissions.md` — the full access model (roles, nullable division, office discriminator, flags, groups, access matrix, deferred items) decided 2026-06-11. Read it first.

## Existing implementation (reviewed 2026-06-11)

* `PPDO.Domain/Entities/PermissionGroup.cs` — flag sets per Division: `CanAccessInventory`, `CanAccessReports`, `CanManageUsers`, `CanManageResourceLinks`
* `PPDO.Domain/Entities/User.cs` — nullable per-user overrides (null = inherit group flag); `Division` currently required
* `PPDO.Application/Services/PermissionService.cs` — SuperAdmin/Admin always true; Staff/Observer → `Override ?? Group flag`; Observer hard-blocked from manage flags
* `MeResponseDto` / `GET /api/auth/me` → frontend nav + route guards
* `CurrentUserService.Division` is ALREADY nullable; frontend `types/user.ts` already types `division: Division | null`

## Identity model changes

1. `users.office_id` — nullable INT FK → `offices`. **The PPDO/non-PPDO discriminator**: null = PPDO user; set = office user (restricted to that office)
2. `users.division` **→ nullable** — null for office users. PPDO users unchanged
3. **Role mapping (no new roles):** office **encoders** = `Staff` + office_id · office **viewers** = `Observer` + office_id (Observer read-only invariant unchanged)

## New flags (one set for ALL configs — not per page)

| Flag | Grants | Notes |
| -- | -- | -- |
| `CanAccessBudgetPlanning` | Budget Planning module | Office scoping applies on top |
| `CanUploadAip` | AIP upload / preview / confirm | **PPDO users only** (file contains ALL offices); Observer hard-blocked like CanManageUsers |
| `CanManageConfig` | All three config pages: CRUD + CSV | One flag for the whole Configuration section |

## New seeded group: "Office User Default"

Division-less; `CanAccessBudgetPlanning = true`, all else false. `GroupIdFor`: any user with office_id set → this group. **Mandatory** — without it, a division-less Staff user resolves a null group and silently has zero permissions.

## ⚠️ Nullable-Division bug guards (from code review — compiler will NOT catch these)

1. **Null scope must never mean "see all".** `InventoryService.cs:185` and `DistributionService.cs:69` compute `Division? scope` where null = Admin = no filter. A null-division Staff/Observer flowing through would see ALL divisions' data. Make the scope role-explicit; null-division Staff/Observer → **empty** scope.
2. `GetByDivisionAsync(requester.Division)` **call sites** (PurchaseRequestService:59, DeliveryService:60) take non-null Division → guard with branch returning empty. NEVER default null to a division (`?? Division.Admin` would leak Admin's PRs).
3. Mechanical null-handling: `AuthService.cs:177` JWT `div` claim (`(int)user.Division` — omit claim when null), `AuthService.cs:150` + `UserService.cs:410` `.ToString()` → null-safe, `UserService.cs:79` create validation (division optional when office_id set), `GroupIdFor` signature → `Division?`.

## Office user experience (decided 2026-06-11)

* **Login redirect:** office users land on `/budget-planning` (Budget Planning dashboard), NOT the Home Dashboard
* **Only Budget Planning is available to them** — sidebar shows the Budget Planning group only; no Inventory, no Resource Links (**PPDO-internal documents**), no Configuration, no User Management
* Office selector locked to their office everywhere; dashboard reduced per Penpot Page 4 Screen 21
* Account creation: PPDO admins via User Management (role + office dropdown from `GET /api/config/offices?active=true`)
