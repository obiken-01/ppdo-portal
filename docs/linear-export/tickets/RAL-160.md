# RAL-160 — WFP Excel Export: "Export to Excel" button + live verification

> 🌿 Working branch: `feature/v1.4.4-ral-XXX-wfp-excel-export-frontend` off `release/1.4.4`. PR targets `release/1.4.4`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14). Blocked by [RAL-159](https://linear.app/ralphoksiprojects/issue/RAL-159/wfp-excel-export-backend-template-population-row-cloning-engine) (backend export endpoint must exist first).
> 📌 Frontend, small.

## Why

The WFP Report page (`/budget-planning/report`) already has print/PDF export ([RAL-149](https://linear.app/ralphoksiprojects/issue/RAL-149/wfp-report-printpdf-export-restore-background-colors-site-matching)). PBO also needs the report as a real `.xlsx` matching their official form — [RAL-159](https://linear.app/ralphoksiprojects/issue/RAL-159/wfp-excel-export-backend-template-population-row-cloning-engine) builds the backend endpoint; this ticket wires up the UI trigger and verifies the actual output against the source form.

## Scope

1. Add an "Export to Excel" action next to the existing print/PDF action on the Report page (`frontend/src/app/(portal)/budget-planning/report/page.tsx`), calling `GET /api/budget-planning/wfp/report/export` (same office/fiscalYear/division query params already used for `WfpReportPreview`) and triggering a file download of the returned `.xlsx`.
2. Loading/error state on the button (disable + spinner while the request is in flight; surface a toast/error message on failure) — follow the existing pattern used for the print/PDF trigger.
3. **Verification (do this manually, not just tsc/eslint):** generate a real export against live local data, open it in Excel, and diff it against `D:\RalphFiles\PPDO\WFP-NEW.xlsx` (outside the repo — Ralph's reference copy) for:
   * Hierarchy and activity/expenditure values match the on-screen Report page exactly.
   * Column widths, cell fill colors (band/subtotal/grand-total/breakdown), border layout, and merged-cell structure all match the source form.
   * F–K columns are blank (expected, not a bug).
   * One sheet/block per fund source renders correctly for a multi-fund office.
   * File opens cleanly in Excel with no repair prompt.

## Files to read before coding

* `frontend/src/app/(portal)/budget-planning/report/page.tsx` — existing print/PDF trigger to mirror for the new button + loading state.
* `frontend/src/lib/api.ts` — Axios instance; add the new export call here, not a raw `fetch`.
* `docs/v1.4.4/WFP_Excel_Export_Assessment.md` — for what "matches the form" means during verification.

## Out of scope

Any backend changes — this ticket only wires the UI to the endpoint [RAL-159](https://linear.app/ralphoksiprojects/issue/RAL-159/wfp-excel-export-backend-template-population-row-cloning-engine) builds. F–K column population.
