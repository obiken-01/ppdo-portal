# RAL-123 — WFP entry UI: context picker + expenditure wizard shell

> 🌿 **Working branch: **`release/1.4.0`. PRs target it, **not **`main`.
> 📌 Read the epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14) first, then `docs/v1.4/WFP_Rework_Requirements_Draft.md` §4 FULLY. Depends on [RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation) (expenditure schema), [RAL-121](https://linear.app/ralphoksiprojects/issue/RAL-121/wfp-reserve-rule-wiring-10percent-hard-cap-default-only-prefill) (reserve rate, default-only prefill), [RAL-122](https://linear.app/ralphoksiprojects/issue/RAL-122/wfp-division-allocation-ledger-aip-budgetallocation-ceiling-blocking) (ceiling ledger + live-check endpoint) — all three must merge first.
> ✔ **Updated 2026-07-07 (Ralph's answers to open questions #6, #12):** (1) the ceiling meters are no longer passive display — the wizard must **live-validate** against [RAL-122](https://linear.app/ralphoksiprojects/issue/RAL-122/wfp-division-allocation-ledger-aip-budgetallocation-ceiling-blocking)'s endpoint and **disable Save** when either ceiling would be exceeded, in addition to the server rejecting the save as a backstop. (2) nature-switch mid-entry **must show a confirm dialog** before discarding entered data — this is no longer an open implementer choice.

## Why

This is the entry-point screen for the whole rework: Program → Project → Activity context, then an expenditure wizard (account → nature → frequency → fund source → reserve → amounts). §4 of the requirements draft settled the ordering question from the demo: **Activity is picked before Frequency**, and Frequency moves INTO the expenditure step (it describes one expenditure, not the whole activity) — read §4.1's reasoning before building the step order.

## Scope

1. **Context picker** (sticky once chosen, reused across multiple expenditures):
   * Program → Project → Activity, sourced from the **Final AIP** hierarchy (existing AIP read endpoints) — never let the user type a ref code.
   * Project-level descriptive-fields accordion (optional): Resources Needed, Responsible Person/Unit, Success Indicator, Means of Verification, Outcome Indicator, Target Beneficiaries — entered once per project (§3, demo decision).
2. **Expenditure wizard shell** (repeats — "+ Add expenditure" under the current activity):
   * Account picker (searchable: code + object title, [RAL-117](https://linear.app/ralphoksiprojects/issue/RAL-117/config-chart-of-accounts-rework-expense-class-default-nature-default)'s config) → shows `default_nature`/`default_apply_reserve` as hints.
   * Nature dropdown, pre-filled from `default_nature` if the account has one, always editable ([RAL-117](https://linear.app/ralphoksiprojects/issue/RAL-117/config-chart-of-accounts-rework-expense-class-default-nature-default) §5.3 semantics — never enforced).
   * Frequency (M/Q/B/A).
   * Fund source, defaulted from the AIP activity's funding source ([RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation)), overridable.
   * Reserve toggle, pre-filled from `default_apply_reserve` ([RAL-117](https://linear.app/ralphoksiprojects/issue/RAL-117/config-chart-of-accounts-rework-expense-class-default-nature-default)/[RAL-121](https://linear.app/ralphoksiprojects/issue/RAL-121/wfp-reserve-rule-wiring-10percent-hard-cap-default-only-prefill) — a default, NOT restricted to certain accounts; every account shows the toggle), default amount pre-filled at 10% of the line's Total, editable, capped.
3. **Sticky ceiling-meter header (✔ now interactive, not just display —** [RAL-122](https://linear.app/ralphoksiprojects/issue/RAL-122/wfp-division-allocation-ledger-aip-budgetallocation-ceiling-blocking)**'s "Both" answer):**
   * Polls [RAL-122](https://linear.app/ralphoksiprojects/issue/RAL-122/wfp-division-allocation-ledger-aip-budgetallocation-ceiling-blocking)'s `GET /wfp/ceilings` endpoint on mount and after every save.
   * **Live-validates while the user is entering amounts** (debounced call to the same endpoint with the in-progress total) — **disable the Save/Add button** when the current entry would exceed either the AIP-budget or division-allocation ceiling, with an inline message naming which ceiling and by how much.
   * The server-side save will independently reject too ([RAL-122](https://linear.app/ralphoksiprojects/issue/RAL-122/wfp-division-allocation-ledger-aip-budgetallocation-ceiling-blocking)) — this is not a substitute for that, it's UX so the user doesn't hit a failed save round-trip.
4. **✔ RESOLVED (Ralph, 2026-07-07) — nature-switch mid-entry:** when a user changes Nature after already entering frequency-grid amounts or procurement items, show a confirm dialog (reuse the existing `ConfirmDialog` component) — *"Switching nature will clear your entered items — continue?"* — before discarding. Do not discard silently.

## Acceptance Criteria

- [ ] Program/Project/Activity picker reads from Final AIP only; no manual ref-code entry anywhere
- [ ] Project-level descriptive fields are optional and persist per project (once, not per activity)
- [ ] Account picker shows nature/reserve default hints; picking an account pre-fills (not locks) nature and reserve state
- [ ] Reserve toggle appears for EVERY account (no eligibility restriction), pre-filled from `default_apply_reserve`
- [ ] Ceiling meters update after every save AND live-validate during entry (debounced), disabling Save when either ceiling would be exceeded
- [ ] Switching Nature mid-entry with unsaved data shows a `ConfirmDialog` before discarding — confirmed behavior, not an open choice
- [ ] "Add another expenditure" keeps Program/Project/Activity context, resets the expenditure-specific fields
