# RAL-162 — Budget Planning Dashboard rework: PPDO-scoped UI, per-division pie charts (frontend)

> 🌿 Working branch: `release/1.4.5` (branched off `release/1.4.4`, not yet merged to `main`). PR targets `release/1.4.5`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14). Blocked by [RAL-161](https://linear.app/ralphoksiprojects/issue/RAL-161/budget-planning-dashboard-rework-ppdo-scoped-queries-per-divisionfund) (new DTO shape must exist first).
> 📌 Frontend, medium. Reworks `budget-planning/page.tsx` in place.

## Why

[RAL-161](https://linear.app/ralphoksiprojects/issue/RAL-161/budget-planning-dashboard-rework-ppdo-scoped-queries-per-divisionfund) reworks the Dashboard's backend to be PPDO-scoped with per-division data. This ticket updates the page to match: remove the now-pointless office picker, replace "WFP Status by Office" with a per-division view, and add ceiling/allocation pie charts per fund source. Mockup approved by Ralph in chat (2026-07-16) — key details below.

## Scope

1. **Remove the office picker entirely** from `budget-planning/page.tsx` — no `listOffices()` call, no `OfficeSelect`, no "All Offices" state. The page is permanently PPDO-scoped; the header should just state the office name/code as static text (matching how other locked-down pages already render it), not a dropdown.
2. **New "Ceiling and allocation by fund" section** — one card per active funding source (General Fund, 5% GAD Fund, 5% LDRRM Fund, ...), each with:
   * A doughnut chart: one slice per division's allocation (consistent division→color mapping across all charts) + one gray "Remaining" slice for the fund's unallocated ceiling.
   * Percentage labels directly on slices ≥5% (skip tiny slices to avoid clutter).
   * Center label showing the fund's total ceiling (this is an **office-level** figure, not per-division — do not repeat/sum it per division, a mistake caught during the mockup review).
   * A small legend below listing each division's allocated amount, plus the "Remaining" amount called out separately.
3. **New "WFP status by division" table** — one row per division: WFP status badge (Final/Draft/Not started), activities-covered (`X / Y`), total allocated (summed across funds). Clicking a row expands a per-fund breakdown (division's allocated amount in each fund) — no ceiling/remaining columns at the division-row grain, since those are office/fund-level, not division-level (same mistake as #2, don't repeat it in the table).
4. **Staff (division-scoped) vs finance/admin view**: for non-`canManageAllocation` callers, the backend ([RAL-161](https://linear.app/ralphoksiprojects/issue/RAL-161/budget-planning-dashboard-rework-ppdo-scoped-queries-per-divisionfund)) already clamps every array to the caller's own division — the frontend just renders whatever comes back, no client-side filtering logic needed. Verify visually with both account types that the pies/table correctly show only one division's data for a Staff test account.
5. Drop the now-unused `AllocationSetupOverviewDto`-shaped rendering and any remaining references to `WfpByOffice`.
