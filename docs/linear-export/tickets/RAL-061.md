# RAL-61 — UI: LDIP Entry Form (Create/Edit)

> 🌿 **Working branch (v1.3): **`release/1.3.0` (off `main` once v1.2.0 is prod baseline); PRs target `release/1.3.0`, **not **`main`.
> 📌 Read the **Alignment update** on the epic [RAL-59](<https://linear.app/ralphoksiprojects/issue/RAL-59>) first.

## Description

Build the LDIP entry form for creating and editing multi-year program entries under a selected office (planning period 2027–2029).

## ⚠️ Blocking schema gap (resolve first)

`ldip_records` currently stores only `ref_code / title / fiscal_year_start / fiscal_year_end / entry_mode / status / source_id` (DB_Model note 4 — LDIP was created as a stub). **None of the budget (PS/MOOE/CO), funding, expected-outputs, or CC/alignment fields below have columns yet — and there is no** `office_id` **column at all**, so LDIP cannot even be office-scoped today. This ticket must **extend the LDIP schema + entities + DTOs (TDD, migration on** `release/1.3.0`**)** before the form can persist them. Confirm the final LDIP field set with PPDO — the field list below is the v1.1 design intent, not the current DB.

## 🔄 Alignment notes (2026-07-01)

* **Status workflow = Draft / Final / Archived.** The ribbon action is **Finalize** (not "Submit"); admin unlock reverts Final → Draft. No approval step.
* **Funding Source = FK to the** `funding_sources` **config table** (store a code snapshot), not a hardcoded list.
* **Money:** use the shared `MoneyInput` + `formatMoney`/`parseMoney` (v1.2). Budget is entered **in ₱000 (thousands)** — keep the ×1000 conversion in the page layer for any peso display/validation.
* Reuse shared UI (`Modal`/`Toast`/`MessageDialog`); flat design. Gate on `CanAccessBudgetPlanning`; office users scoped to own office.

## Business Rules

* AIP Reference Code auto-increments within the office (PPP segment)
* Total = PS + MOOE + CO (auto-calculated, not editable)
* Start Year ≤ End Year
* PPA Name required; budget fields default to 0 if blank
* Save Draft: no validation; **Finalize**: validates required fields + locks the record

## Acceptance Criteria

- [ ] LDIP schema/entities/DTOs extended to hold the persisted fields (TDD + migration)
- [ ] Auto-filled fields (code, sector, office) non-editable
- [ ] Total recalculates on PS/MOOE/CO change (via `MoneyInput`)
- [ ] Start Year ≤ End Year validation
- [ ] Save Draft stores without Finalize validations
- [ ] Finalize validates required fields, locks the record, shows errors inline
- [ ] Edit mode pre-populates all fields; Final records read-only until admin unlock
