# RAL-119 — Config: Procurement Presets (reusable line-item templates per account)

> 🌿 **Working branch: **`release/1.4.0`. PRs target it, **not **`main`.
> 📌 Read the epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14) first, then `docs/v1.4/WFP_Rework_Requirements_Draft.md` §7.2 FULLY. Depends on [RAL-117](https://linear.app/ralphoksiprojects/issue/RAL-117/config-chart-of-accounts-rework-expense-class-default-nature-is) (accounts) and [RAL-118](https://linear.app/ralphoksiprojects/issue/RAL-118/config-price-index-page-procurement-item-catalogue) (price index) — both must merge first.

## Why

Per the demo: procurement items entered for one activity are "possibly used by other activity that will procure same items" — presets let a user save a named set of items (tied to an account) and reload it later instead of re-typing.

## Scope

* `procurement_presets`: `id, account_id (FK), name, is_active, created_by_id, created_at, updated_at`
* `procurement_preset_items`: `id, preset_id (FK), price_index_item_id (FK, nullable), name, unit, unit_price (snapshot at save time — NOT a live link to price_index_items), default_qty`
* Two creation paths write the same tables (per the draft): **(a)** "Save as preset" from the WFP procurement entry screen (built in ticket #11 — this ticket just needs the API endpoint that path will call), and **(b)** a dedicated config page for browsing/curating presets directly.
* Loading a preset **always copies** its items into the entry (snapshot semantics, editable after) — presets are templates, never live references.
* API: `GET /api/config/procurement-presets?accountId=`, `GET .../{id}`, `POST`, `PUT .../{id}`, `DELETE .../{id}` (soft delete via `is_active`). No CSV round-trip needed (this isn't a bulk-import list like accounts/offices — presets are created through use).
* Frontend config page at `config/procurement-presets`: list presets (filterable by account), expand to see/edit item rows, delete (soft).

## Open question (flag, don't block on it)

⚠ Shared across all offices/divisions, or scoped to the creator's office? The draft implies shared ("can be used by other activity that will procure same items") — build shared, show `created_by` on each preset for traceability, and add scoping later if PPDO says otherwise.

## Acceptance Criteria

- [ ] `procurement_presets` + `procurement_preset_items` tables, FK to `accounts` and (nullable) `price_index_items`
- [ ] Preset items snapshot name/unit/price at save time — later price-index changes never retroactively alter a saved preset
- [ ] CRUD API gated by `CanManageConfig` for the config-page path; the "save as preset" endpoint (consumed by ticket #11) is gated by `CanAccessBudgetPlanning` (any WFP entry user can save one, not just config admins)
- [ ] Config page lists/filters presets by account, shows item rows, allows delete
