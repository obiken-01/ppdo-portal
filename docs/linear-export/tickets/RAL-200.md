# RAL-200 — API: Audit trail logging for Inventory (PRs, Deliveries, Distributions, Items Master, Stock Balances)

> 🌿 **Working branch: **`release/1.7.0` — all v1.7.0 work branches off `release/1.7.0` and PRs target `release/1.7.0` (not `main`).

## Overview

`IAuditService` (built in [RAL-77](<https://linear.app/ralphoksiprojects/issue/RAL-77>) for budget planning/config, surfaced via the [RAL-174](<https://linear.app/ralphoksiprojects/issue/RAL-174>) Audit Log page) is never called from any Inventory service. Every Inventory write — creating/editing a PR, receiving a delivery, distributing stock to a division, editing the Items Master catalog, and [RAL-193](https://linear.app/ralphoksiprojects/issue/RAL-193/warehouse-stock-input-opening-balance-entity-api-page-excel-bulk)'s warehouse physical-count entries — currently leaves no audit trail. For a feature that tracks physical stock and money, "who changed what and when" matters at least as much as it did for budget planning.

This ticket wires the existing `IAuditService` into the Inventory services — no new infrastructure, same pattern already used by `DivisionService`, `UserService`, `AccountService`, etc.

## Reference

* `backend/PPDO.Application/Services/IAuditService.cs` / `AuditService.cs` — existing service, do not modify its contract
* `backend/PPDO.Application/Services/DivisionService.cs` (CreateAsync/UpdateAsync/DeactivateAsync) — reference pattern for Guid-keyed entities
* `backend/PPDO.Application/Common/AuditAction.cs` — Create/Update/Delete constants
* `docs/v1.1/DB_Model.md` section 5 — `audit_log` table schema (already exists, no migration needed)

## Scope

Log CREATE / UPDATE actions (DELETE where applicable) for:

* `PurchaseRequestService` — `CreateAsync`, `UpdateAsync`, `MarkCompletedAsync`/`UnmarkCompletedAsync` (log as UPDATE with old/new status). Excel import (`ImportFromExcelAsync`) — one summarized entry per import, not one per row.
* `DeliveryService` — `CreateAsync` (delivery received). Include the resulting PR status transition (Open → PartiallyDelivered → FullyDelivered) in the same or a linked entry.
* `DistributionService` — `CreateAsync` (stock issued to a division).
* `ItemService` (Items Master) — `CreateAsync`, `UpdateAsync` (covers both manual catalog edits and an admin reviewing/correcting an auto-created `IsNewItem` row).
* `StockBalanceService` ([RAL-193](https://linear.app/ralphoksiprojects/issue/RAL-193/warehouse-stock-input-opening-balance-entity-api-page-excel-bulk), already shipped without audit logging) — `CreateAsync`, `UpdateAsync`, `DeleteAsync`. This is the highest-value target in this ticket: it lets an Admin/SuperAdmin directly overwrite computed on-hand, with no approval step — the audit trail is the only accountability mechanism it has today.

All affected entities are Guid-keyed — use the `IAuditService.LogAsync(string tableName, Guid recordId, ...)` overload throughout.

## Design

* Same reusable `IAuditService` — call it from the Application-layer services above, not from Function handlers or via a DB trigger
* JSON snapshots contain changed fields only, not full row dumps (mirrors [RAL-77](https://linear.app/ralphoksiprojects/issue/RAL-77/api-audit-logging-for-budget-planning-config-records))
* `changed_by` from `CurrentUserService` (handled internally by `IAuditService`)
* Never include free-text PR fields that aren't meaningfully auditable as diffs (e.g. skip re-logging unchanged `Program`/`Project`/`Activity` text on every PR update — only log fields that actually changed)

## Testing (TDD)

Write failing xUnit tests first (mirrors `AuditServiceTests.cs`/`DivisionServiceTests.cs` conventions — mock `IAuditService`, verify `LogAsync` is called with the expected table name, action, and record id). Cover: entry logged on create/update/delete for each service above, PR status-transition entries carry old/new status, StockBalance delete logs the removed entry's values.

## Acceptance Criteria

- [ ] Creating and updating a PR writes an audit entry; Mark/Unmark Completed logs the status change
- [ ] Receiving a delivery writes an audit entry, including the PR status transition it triggers
- [ ] Creating a distribution writes an audit entry
- [ ] Creating and updating an Items Master entry writes an audit entry
- [ ] Creating, updating, and deleting a Stock Balance (warehouse stock input) entry writes an audit entry
- [ ] PR Excel import writes one summarized entry per import, not per row
- [ ] All new entries are visible and correctly attributed on the existing Audit Log page ([RAL-174](https://linear.app/ralphoksiprojects/issue/RAL-174/config-audit-log-page-superadmin-only-feature-flagged)) — no frontend changes needed if `IAuditService` is wired correctly
- [ ] Unit tests cover every service touched
