# RAL-128 — WFP entry: give the AIP budget ceiling bar a distinct color

> 🌿 **Working branch: **`release/1.4.0`. PR targets it, **not **`main`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14). Frontend-only, no migration, no backend.

## Why

In the WFP entry wizard's context header there are two ceiling meters — **Division allocation** and **AIP budget (this activity)** — but both render green (they share the `progressBar` helper's default `okClass`). At a glance they look like the same metric. Give the AIP budget bar a distinct color so the two ceilings are visually separable.

## Files to read

* `frontend/src/app/(portal)/budget-planning/wfp/entry/page.tsx`:
  * `progressBar(used, total, overClass = "bg-red-500", okClass = "bg-green-600")` (~line 130)
  * Division allocation bar call (~line 996) — keep green
  * AIP budget bar call (~line 1011) — give a distinct color
* `frontend/tailwind.config.ts` (use a mapped design token, not a raw hex — see CLAUDE.md "never hardcode colours")

## Working branch

Create `feature/v1.4-ral-XXX-wfp-aip-bar-color` off `release/1.4.0`; PR against `release/1.4.0` (NOT main).

## Steps

1. Pass a distinct `okClass` (e.g. a blue/indigo design token) to the AIP-budget `progressBar` call; keep the over-ceiling state red for both bars; keep the division bar green.
2. Optional: a small color-key label next to each bar so the mapping is self-explanatory.

## Out of scope

Backend, ceiling computation ([RAL-122](https://linear.app/ralphoksiprojects/issue/RAL-122/wfp-division-allocation-ledger-aip-budgetallocation-ceiling-blocking)), the division bar's color. No tests needed (purely visual) — verify in the browser preview.
