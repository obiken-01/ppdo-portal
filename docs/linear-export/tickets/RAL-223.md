# RAL-223 — Distribution can't issue warehouse-count-only stock (Stock Overview shows On Hand, Distribution shows 0)

## Bug report (from prod)

Ralph uploaded a PR containing StockNo `OSE-8752002308` (Photo paper), then recorded a physical count of 5 packs via Warehouse Stock Input (no delivery had been received yet). Result:

* **Stock Overview**: shows Ordered=5, Delivered=0, Distributed=0, **On Hand=5**.
* **Distribution**: shows Total Delivered=0, Total Distributed=0, **On Hand (Available)=0**, "No delivery batches found" in Stock Sources — item cannot be distributed at all.

## Root cause

Stock Overview and Distribution compute "on hand" from two disconnected data sources:

* `InventoryService.GetItemLedgerAsync` (`backend/PPDO.Application/Services/InventoryService.cs:207-208`): `OnHand = QtyDelivered - QtyDistributed + SUM(StockBalance.VarianceQty)` — includes warehouse physical-count variance ([RAL-193](https://linear.app/ralphoksiprojects/issue/RAL-193/warehouse-stock-input-opening-balance-entity-api-page-excel-bulk)).
* `DistributionService.GetItemSummaryAsync` / `AllocateAsync` (`backend/PPDO.Application/Services/DistributionService.cs:88-130, 188-208`): `OnHand = totalDelivered - totalDistributed`, sourced **exclusively** from `DeliveryItem` batches via `GetDeliveryItemBreakdownsByStockNoAsync`. `StockBalance` is never queried here at all.

This isn't just a missing query — it's a data-model gap. `Distribution.DeliveryItemId` (`backend/PPDO.Domain/Entities/Distribution.cs:22`) is a required FK to a real `DeliveryItem`. `StockBalance` (`backend/PPDO.Domain/Entities/StockBalance.cs`) is PPDO-wide, has no division scope, and has no link to any `DeliveryItem` — so warehouse-count stock currently has no way to be distributed, even though Stock Overview reports it as on-hand.

[RAL-193](https://linear.app/ralphoksiprojects/issue/RAL-193/warehouse-stock-input-opening-balance-entity-api-page-excel-bulk) (Warehouse Stock Input) built the Stock Overview side of this but never extended Distribution to consume it.

## Product intent (confirmed with Ralph)

Warehouse Stock Input exists specifically to let PPDO record stock they physically have on hand when it didn't arrive through a PR + Delivery in this system (e.g. legacy/opening stock, or stock received before the system was in use). That stock is meant to be real, usable, distributable inventory — not just an audit annotation. So the fix direction is to make Distribution aware of it, not to strip the on-hand number out of Stock Overview.

## Fix direction (agreed)

1. Make `Distribution.DeliveryItemId` nullable; add a nullable `StockBalanceId` (or similar) link so a `Distribution` row can trace back to a warehouse-count entry instead of a `DeliveryItem`.
2. `DistributionService.GetItemSummaryAsync`: fold `StockBalance` variance into `TotalDelivered`/`OnHand`, and surface it as a synthetic "Stock Sources" entry (source = "Warehouse Count", no PRNo/DeliveryRef) alongside real delivery batches.
3. `DistributionService.AllocateAsync`: include the synthetic warehouse-count pool entry in the FIFO ordering (by `StockBalance.EffectiveDate`, alongside `DeliveryItem.DeliveryDate`), and correctly write `Distribution` rows against it (nullable `DeliveryItemId` + `StockBalanceId` set instead).
4. Frontend `distribution/page.tsx`: Stock Sources list needs to render a non-delivery-batch row type.
5. Needs an EF Core migration (nullable FK change + new column on `Distributions`).

Division scoping needs explicit handling: `StockBalance` has no division, but `Distribution`/delivery batches are division-scoped via `DivisionScope`. Decide how a division-less warehouse-count pool participates in a Staff/Observer's division-scoped view before implementing (product decision, not just code).

## Out of scope

* Not touching `InventoryService.GetItemLedgerAsync`'s existing On Hand formula — it's correct as designed.
* Not reopening [RAL-193](https://linear.app/ralphoksiprojects/issue/RAL-193/warehouse-stock-input-opening-balance-entity-api-page-excel-bulk)'s original Stock Overview scope.
