# RAL-188 — Main Dashboard responsive stacking

## Context

docs/v1.7/Mobile_And_Inventory_Findings.md §2.2 — the dashboard is a

non-wrapping flex row with a hard-coded w-60 Resource Links panel; calendar

and panel can't both fit on a phone. The dashboard page has zero responsive

utilities today.

## Files to read first

* frontend/src/app/(portal)/dashboard/page.tsx (the `flex gap-4` row at :161,

  `w-60 shrink-0` panel at :175; event-detail modal at :183 is already

  mobile-safe)
* frontend/src/components/dashboard/DashboardCalendar.tsx (`height="auto"`,

  `dayMaxEvents={2}` at :168-174 — tuned in [RAL-175](https://linear.app/ralphoksiprojects/issue/RAL-175/bug-dashboard-calendar-row-height-inconsistent-and-saturday-events), do not change)
* frontend/src/components/dashboard/ResourceLinksWidget.tsx
* frontend/src/components/dashboard/CalendarApprovalPanel.tsx (check usable at

  375px as part of this ticket)
* frontend/src/components/dashboard/CreateEventModal.tsx (same check)

## Working branch

release/1.6.0. Create feature/v1.6.0-ral-B-dashboard-responsive off

release/1.6.0, PR against release/1.6.0 (NOT main).

## Steps

1. Stack the `flex gap-4 flex-1 min-h-0` row vertically below `lg:`; keep

   side-by-side at `lg:` and above.
2. Resource Links: drop the fixed `w-60` below `lg:` (full width under the

   calendar); keep `w-60` at `lg:`+.
3. Page root is `p-5 h-full flex flex-col` — allow scroll below `lg:` instead

   of being clipped by `h-full`. Reduce padding to `p-3` below `sm:`.
4. Verify CreateEventModal and CalendarApprovalPanel at 375px; fix any fixed

   widths found. Loading states must not shift layout (PERFORMANCE_GUIDELINES).

## Manual test plan

- [ ] 375px: calendar full width, Resource Links stacked below, no horizontal

  ```
  scroll
  ```
- [ ] 375px: tapping a date opens CreateEventModal, fully usable
- [ ] 375px: admin pending-events chip opens CalendarApprovalPanel, usable
- [ ] 1280px: pixel-identical to before this change
- [ ] Multi-day events still render correctly ([RAL-173](https://linear.app/ralphoksiprojects/issue/RAL-173/bug-dashboard-calendar-multi-day-events-render-one-day-short) regression guard)

## Do NOT

Change the events cache, month-change fetch logic, pending-count logic, or

owner-only edit/delete rules ([RAL-168](https://linear.app/ralphoksiprojects/issue/RAL-168/dashboard-calendar-allow-event-owner-to-edit-their-own-event)). Do NOT change dayMaxEvents or calendar

height mode.
