# RAL-124 — WFP entry UI: non-procurement frequency grid

> 🌿 **Working branch: **`release/1.4.0`. PRs target it, **not **`main`.
> 📌 Read the epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14) first, then `docs/v1.4/WFP_Rework_Requirements_Draft.md` §5.1 FULLY. Depends on the wizard shell (the ticket that becomes "[RAL-123](https://linear.app/ralphoksiprojects/issue/RAL-123/wfp-entry-ui-context-picker-expenditure-wizard-shell)" once #9 is created — check the epic for its real ID) to slot into.

## Why

Non-procurement expenditures (salaries, utilities, travel, etc.) are typed directly per period — no line items — but the period grain varies by frequency (12 monthly / 4 quarterly / 2 half-year / 1 annual), and the demo called for explicit carry-forward instead of silent auto-fill.

## Scope

* A period-amount grid sized to the selected frequency (12/4/2/1 `MoneyInput` cells).
* **Explicit carry-forward (§5.1 ★REC — NOT implicit):** after the first period is filled, offer an **"Apply to all remaining periods"** action, plus a per-period "copy previous" affordance. Do not silently persist the previous value into the next field as the user tabs through — make the copy a deliberate click, matching the draft's discussion of this exact ambiguity.
* Tab/Enter keyboard flow advances through the grid.
* Live computed strip beneath the grid: per-quarter roll-up → Net → (+ Reserved, if toggled) → Total — this reads [RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation)'s computed values after each save/preview, it does not reimplement the roll-up math client-side.
* Saves into `wfp_expenditure_periods` via [RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation)'s save endpoint.

## Acceptance Criteria

- [ ] Grid shows the correct number of period inputs for the selected frequency (12/4/2/1)
- [ ] "Apply to all remaining periods" and per-period "copy previous" are explicit user actions, not automatic
- [ ] Live totals strip matches what the server will compute (verify against [RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation)'s pipeline, don't hand-roll the math twice)
- [ ] Annual frequency shows the "charge to Q_" selector (default Q1) from [RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation)'s `annual_quarter_choice`
