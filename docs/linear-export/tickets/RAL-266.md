# RAL-266 — Force recovery-answer setup at next login (rollout over existing accounts)

**V18-25** — plan: `docs/v1.8/Phase_Plan.md` §3.4 — see the **V18-25** row of that table.

> ⚠️ **Corrected 2026-08-26.** This ticket previously cited "sub-decision (e) in `AIP_Requirements_Review.md` §2.6". **That document does not exist in the repo and never has** — do not go looking for it. `docs/v1.8/Phase_Plan.md` §3.4 is the authoritative source.

Depends on V18-22 ([RAL-253](https://linear.app/ralphoksiprojects/issue/RAL-253/password-reset-schema-for-recovery-answer-mustchangepassword-attempt)).

Self-service reset only works for accounts that **have** a recovery answer. Making it optional leaves most of the ~52 existing accounts unrecoverable — which is the state this whole cluster exists to leave.

**Scope:**

* At next login, a user with no `RecoveryQuestionKey` is sent to a one-time setup screen: pick a question from the fixed list, type an answer, confirm. They cannot navigate elsewhere until it is set (same guard shape as `MustChangePassword` in V18-26 — build them so they compose rather than fight).
* Part of account creation for new users.
* ⚠️ **Hash and normalize exactly as **[RAL-265](https://linear.app/ralphoksiprojects/issue/RAL-265/password-reset-backend-request-verify-endpoints-throttle-audit) **does** — the answer goes through `RecoveryAnswerNormalizer` (`PPDO.Application/Common/`, shipped in [RAL-253](https://linear.app/ralphoksiprojects/issue/RAL-253/password-reset-schema-for-recovery-answer-mustchangepassword-attempt)) and then the **same BCrypt path as a password**. It is a credential, not a profile field. If setting and verifying normalize differently, users are locked out of their own answer with no visible cause.
* **Fallback for anyone without an answer set** (during rollout, or later if they forget): admin one-click reset — Option A. That path is needed permanently, not just for the rollout window.

⚠️ Do not make the setup screen skippable. A skipped setup is indistinguishable from a user who never logged in, and the fallback path silently becomes the only path.

**Done when:** every active account either has an answer or is covered by the admin fallback, and a fresh account cannot reach the portal without setting one.
