# RAL-70 — API: Config CRUD endpoints + CSV upload/download

> 🌿 **Working branch:** `release/1.1.0` — all v1.1 work branches off `release/1.1.0` and PRs target `release/1.1.0` (not `main`).

## API: Config endpoints

Build all three config CRUD API controllers.

**Reference:** Read `docs/v1.1/DB_Model.md` for table schemas, column names, and CSV column orders.

---

### Accounts — `/api/config/accounts`

Table: `accounts` — columns: `id, account_title, account_number, normal_balance, description, is_active, created_at, updated_at`

**Endpoints:**

* `GET /api/config/accounts` — list; query params: `search` (matches account_number or account_title), `accountType` (PS/MOOE/CO), `active` (true/false/all, default: all)
* `GET /api/config/accounts/{id}`
* `POST /api/config/accounts` — fields: `account_title, account_number, normal_balance, description`
* `PUT /api/config/accounts/{id}` — same fields as POST
* `DELETE /api/config/accounts/{id}` → soft delete: set `is_active = false`
* `GET /api/config/accounts/download-csv` — CSV export, column order: `account_title, account_number, normal_balance, description, is_active`
* `POST /api/config/accounts/upload-csv` — upsert by `account_number`; return `{ new, updated, skipped }`

`accountType` **filter — prefix match on** `account_number` **(NOT a stored column):**

```
PS   → WHERE account_number LIKE '5-01-%'
MOOE → WHERE account_number LIKE '5-02-%'
CO   → WHERE account_number LIKE '5-03-%'
```

There is no `account_type` column in the `accounts` table. Do not add one.

---

### Offices — `/api/config/offices`

Table: `offices` — columns: `id, office_code, office_name, is_active, created_at, updated_at`

* Standard CRUD + CSV upload/download
* Upsert key: `office_code`
* CSV column order: `office_code, office_name, is_active`
* Soft delete: `is_active = false`

---

### Funding Sources — `/api/config/funding-sources`

Table: `funding_sources` — columns: `id, code, name, description, is_active, created_at, updated_at`

* Standard CRUD + CSV upload/download
* Upsert key: `code`
* CSV column order: `code, name, description, is_active`
* Soft delete: `is_active = false`

---

### Shared rules

* Response shape: `{ data, error, message }`
* Dropdown endpoints (used by planning forms): return only `is_active = true` records
* Never hard delete any config record — they may be referenced by historical planning data
* Validate uniqueness of key fields (account_number, office_code, code) on create and update
* **CSV upload is the seeding path** — the user will manually upload `chart_of_accounts.csv` (143 rows), `offices.csv` (16 rows), and `funding_sources.csv` (6 rows) through the config UI. The upsert + preview flow must handle these initial bulk loads cleanly.
