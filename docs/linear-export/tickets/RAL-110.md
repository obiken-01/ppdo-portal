# RAL-110 — Bug: login page reloads immediately after the invalid-credentials banner

## Symptom

On a failed login (wrong username/password), the "Invalid username or password" banner appears and then the page **reloads immediately**, so the user barely sees the message and the form is cleared.

## Root cause

`frontend/src/lib/api.ts` — the axios response interceptor treats **every** 401 as an expired access token and runs the silent-refresh flow. But `POST /auth/login` returns **401 on bad credentials**, so:

1. Interceptor catches the login 401 → calls `POST /auth/refresh`.
2. No valid refresh cookie (user isn't logged in) → refresh 401 → interceptor `catch`.
3. `catch` runs `auth.logout()` + `window.location.href = "/login"` → **full page reload**, right after the login page's own `catch` set the error banner.

## Fix (PR #92)

Skip the silent-refresh flow for the auth endpoints themselves (`/auth/login`, `/auth/refresh`, `/auth/logout`), where a 401 is a genuine credential failure, not session expiry. The error propagates to the caller, the banner shows, and the page no longer reloads.

## Verification

* Wrong credentials → banner stays, no reload, form retained
* Valid credentials → still logs in and routes correctly
* Expired access token on a normal page → silent refresh still works (non-auth 401 path unchanged)
