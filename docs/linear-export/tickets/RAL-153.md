# RAL-153 — WFP: warn when a procurement item is duplicated within the same expenditure

> Branch: `release/1.4.2` · Epic: [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14) (WFP Rework) · Follow-up to [RAL-152](https://linear.app/ralphoksiprojects/issue/RAL-152/wfp-entry-warn-when-a-picked-procurement-item-is-already-used-in)

## Why

[RAL-152](https://linear.app/ralphoksiprojects/issue/RAL-152/wfp-entry-warn-when-a-picked-procurement-item-is-already-used-in) added a non-blocking amber warning when a picked procurement item is already used in **another** expenditure for the same activity. While verifying that feature live, we found the actual scope the user wants also includes the case where the **same expenditure being edited** has two or more rows pointing at the same price-index item (e.g. two "Battery AAA, 1.5Volts, Max Alkaline..." rows in one expenditure) — this case currently shows no warning at all, since [RAL-152](https://linear.app/ralphoksiprojects/issue/RAL-152/wfp-entry-warn-when-a-picked-procurement-item-is-already-used-in)'s `otherExpenditures` set explicitly excludes the expenditure currently open.

## Scope

* Extend the duplicate-detection in `WfpProcurementItemTable` (via `frontend/src/app/(portal)/budget-planning/wfp/entry/page.tsx`'s `ExpenditureWizard`) to also flag a row whose `priceIndexItemId` matches another row **within the same expenditure's own procurement item list** (the in-progress `rows`/items array being edited), not just items from other saved expenditures.
* Same non-blocking amber style/copy as [RAL-152](https://linear.app/ralphoksiprojects/issue/RAL-152/wfp-entry-warn-when-a-picked-procurement-item-is-already-used-in) ("⚠ Already used in another expenditure for this activity." — reuse or adapt wording to distinguish "this expenditure" vs "another expenditure" if useful, e.g. "⚠ This item is already added to this expenditure." for the within-expenditure case).
* Still never blocks Save.
* Free-typed rows (no `priceIndexItemId`) remain excluded, same as [RAL-152](https://linear.app/ralphoksiprojects/issue/RAL-152/wfp-entry-warn-when-a-picked-procurement-item-is-already-used-in).
* If a row matches duplicates in both the same expenditure AND another expenditure, decide which message (or both) to show — favor whichever is clearer to the end user without over-cluttering the row.

## Out of scope

* No change to save/validation behavior — still informational only.
* No backend changes — this is a pure frontend derived-state check, same as [RAL-152](https://linear.app/ralphoksiprojects/issue/RAL-152/wfp-entry-warn-when-a-picked-procurement-item-is-already-used-in).
