# RAL-193 — Warehouse stock input — opening balance entity, API, page, Excel bulk upload

**Unblocked 2026-08-03 — answers below.** Implemented in PR #204. Full spec: `docs/v1.7/Mobile_And_Inventory_Findings.md` §5.

## Problem

`ItemMaster` is a catalog only — no quantity field of any kind. On-hand is derived entirely from `ItemStockLevel.QtyDelivered - ItemStockLevel.QtyDistributed`. Stock that exists in the warehouse but never passed through a PR + Delivery in this system is invisible.

## Open questions (block ticket-writing / schema design)

1. **One-time opening balance, or recurring physical count?** A single opening balance per item is one row + one migration. A recurring physical-count adjustment with history is a ledger with effective dates, variance against system on-hand, and a reconciliation view. Materially different schemas — the single biggest unknown.
2. **Division-scoped or PPDO-wide?** Decides whether `division_id` is on the table and whether `DivisionScope` applies.
3. **Retroactive or forward-only?** Does an opening balance entered today apply to historical Stock Overview figures, or only from its effective date forward?
4. **Who can enter it? **`CanAccessInventory`, or Admin/SuperAdmin only — it directly moves on-hand numbers.
5. **Approval step needed**, like the calendar-event workflow?
6. **Bulk template key** — StockNo only, or StockNo + division? On re-upload: upsert or reject duplicates?

## Expected shape once unblocked

New table (working name `stock_balances`, snake_case per `docs/NAMING_CONVENTIONS.md`) + `IStockBalanceRepository` + Application service/DTOs/validator + `StockBalanceFunctions` (`CanAccessInventory`-gated, `ApiResponse<T>`) + `InventoryService` on-hand formula updated to `opening + delivered - distributed` + frontend per-item entry page + Excel bulk upload (reuse the PR-import `CopyToAsync`→`MemoryStream` pattern, see `ExcelService.ParsePRImport`).

Do NOT change the on-hand formula in [RAL-192](https://linear.app/ralphoksiprojects/issue/RAL-192/inventoryservice-scoped-queries-list-pagination) — that ticket ships first and this one builds on it.

## Resolved answers (2026-08-03)

1. **Recurring physical count** (not one-time) — a ledger with history.
2. **PPDO-wide** — no `division_id` on the table.
3. **Forward-only** — no retroactive rewrite of historical figures.
4. **CanAccessInventory** holders can enter counts.
5. **No approval step** — applies immediately.
6. **Bulk upload** key is StockNo + EffectiveDate; re-upload **upserts**.

## Implementation

On-hand formula: `SUM(StockBalance.VarianceQty) + QtyDelivered - QtyDistributed`, where `VarianceQty = CountedQty - SystemOnHandAtEntry` is computed once at save time. Applied only to the Admin/SuperAdmin unscoped view — a PPDO-wide count can't be correctly attributed to one division's subset of movements, so Staff/Observer's division-scoped on-hand (and [RAL-192](https://linear.app/ralphoksiprojects/issue/RAL-192/inventoryservice-scoped-queries-list-pagination)'s formula) is unchanged. See PR #204 for full rationale.
