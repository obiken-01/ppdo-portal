# RAL-127 — WFP: add "number of days" to procurement line items

> 🌿 **Working branch: **`release/1.4.0`. PR targets it, **not **`main`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).

## Why

Some procurement expenditures are day-based (venue rental, per-diem, honoraria, equipment rental) where the appropriation is `qty × unit price × number of days`. Today `WfpProcurementItem` computes `LineTotal = Qty × UnitPrice` only — there is no days factor, so day-based items can't be entered correctly.

## ⚠️ Confirm with Ralph before coding

Does "number of days" **multiply into the line total** (`LineTotal = Qty × UnitPrice × NumberOfDays`), or is it informational only? **Default assumption for this ticket:** it's a multiplier defaulting to `1`, so existing items (days = 1) keep their current totals. Also confirm whether procurement **presets** (`procurement_presets` item rows, [RAL-119](https://linear.app/ralphoksiprojects/issue/RAL-119/config-procurement-presets-reusable-line-item-templates-per-account)) should carry days too.

## Steps

1. **Migration + entity:** add `WfpProcurementItem.NumberOfDays` (decimal, default `1`), snake_case column `number_of_days`. Additive/defaulted — non-breaking.
2. **Computation: **`LineTotal = Qty × UnitPrice × NumberOfDays` in the server-side calculator; mirror the exact same formula in `frontend/src/lib/wfp.ts` so the live preview matches.
3. **DTOs:** thread `numberOfDays` through the save + read procurement-item DTOs (default 1 on omit).
4. **Frontend:** add a **Days** column to `WfpProcurementItemTable` (after Qty), `MoneyInput`/number input, default 1; recompute the row's line total live.
