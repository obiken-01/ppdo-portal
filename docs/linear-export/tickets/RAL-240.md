# RAL-240 — Stock Overview: DELIVERED and DISTRIBUTED columns omit warehouse-count movement, so rows don't reconcile

**Reported by Ralph on the production Stock Overview page.** The DISTRIBUTED column reads `0` for every item — sorting by DISTRIBUTED descending still shows `0` in the top row — even though items demonstrably have distributions (e.g. `OSE-1714343441` shows 3 distributions on the Distribution page).

## Root cause (confirmed by code read + data)

`InventoryRepository.GetItemStockLevelsAsync` (`backend/PPDO.Infrastructure/Repositories/InventoryRepository.cs:46-60`) computes `QtyDistributed` with an **inner join to** `DeliveryItems`:

```csharp
from dist in _context.Distributions
join di in _context.DeliveryItems on dist.DeliveryItemId equals (Guid?)di.Id
```

Warehouse-count distributions ([RAL-223](https://linear.app/ralphoksiprojects/issue/RAL-223/distribution-cant-issue-warehouse-count-only-stock-stock-overview)) carry `StockBalanceId` and a **null** `DeliveryItemId`, so the inner join structurally drops them. The same applies to `QtyDelivered`, which only sums `DeliveryItems` — stock that entered via a warehouse count never appears.

The exclusion is deliberate and commented, on the grounds that the effect is "netted directly into StockBalanceRepository's variance totals." That is true — but **only for On Hand**:

```
onHand   = QtyDelivered − QtyDistributed + variance          (InventoryService.cs:111, 207)
variance = SUM(stock_balances.variance_qty) − SUM(pool distributions)   (StockBalanceRepository.GetAllVarianceTotalsAsync)
```

`QtyDelivered` and `QtyDistributed` are passed to `ItemLedgerRowDto` raw (`InventoryService.cs:235-237`) while the correction lands only in `OnHand`. **The row therefore does not internally reconcile.**

### Reproduced on dev data

`double-sided tape` — counted variance 40, pool-distributed 1:

| Column | Grid shows | Reality |
| -- | -- | -- |
| DELIVERED | `0` | 40 counted in |
| DISTRIBUTED | `0` | 1 distributed |
| ON HAND | `39` | 39 ✓ |

A user reading the row sees `0 − 0 = 39`.

## Severity

**Reporting only — no balances are wrong.** On Hand, the stat tiles' in-stock/low-stock classification, and the Distribution page are all correct. This is a display/reconciliation defect, not data corruption.

## Fix

Include warehouse-count movement in both columns while leaving On Hand numerically identical:

```
QtyDelivered'   = QtyDelivered   + max(0, grossVariance)
QtyDistributed' = QtyDistributed + poolDistributed
shrinkage       = min(0, grossVariance)                  // ≤ 0
onHand          = QtyDelivered' − QtyDistributed' + shrinkage
```

Because `max(0,v) + min(0,v) = v`, this expands to `QtyDelivered − QtyDistributed − poolDistributed + grossVariance`, which is exactly today's value. **On Hand must not change for any item** — that is the primary regression test.

Positive variance folds into DELIVERED (decision: Ralph, 2026-08-20 — no new grid column). Negative variance is shrinkage (`OSAME-3955791577` is −23 on dev) and must stay a separate term, since surfacing it as negative "delivered" would be wrong and clamping it away would corrupt On Hand.

Requires the repository to expose gross variance and pool-distributed separately, rather than only the pre-netted total that `GetAllVarianceTotalsAsync` returns today — the current single figure cannot be decomposed by the caller.

Applies to both call sites: `GetStatsAsync` (~line 111) and the Stock Overview list (~line 207).

## Out of scope

The Distribution page, which already reports counted/distributed correctly from `StockBalanceRepository` directly.
