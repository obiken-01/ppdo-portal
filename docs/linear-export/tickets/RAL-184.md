# RAL-184 — PPMP Report — .xlsx export matching the province's PPMP form

Export the PPMP report to `.xlsx`, matching the province's own `ppmp admin2027.xlsx` layout. Follow-up to the preview ([RAL-183](https://linear.app/ralphoksiprojects/issue/RAL-183/ppmp-report-preview-backend-service-endpoint-item-grained-grid-on-the)) — the export reads the same `PpmpReportDto`. Mirrors v1.4.4's WFP Excel export.

**Read** `docs/v1.5/PPMP_Report_Findings.md` **§8 (build spec) + §4.1 (export conventions).** Blocked by [RAL-183](https://linear.app/ralphoksiprojects/issue/RAL-183/ppmp-report-preview-backend-service-endpoint-item-grained-grid-on-the) (needs the DTO + endpoint shape it establishes).

## Read before writing code

* `backend/PPDO.Infrastructure/Services/WfpReportExcelService.cs` (+ `IWfpReportExcelService`) — the pattern to copy: **programmatic ClosedXML build from a documented style catalog** (fills/fonts/borders/number-formats/column-widths as constants applied per row type), with merges computed from each block's actual emitted row count. Do **NOT** clone rows out of a reference workbook — the province's files are filled samples, not blank templates (the WFP one had 293 hand-touched merged ranges).
* `backend/PPDO.Tests/Infrastructure/WfpReportExcelServiceTests.cs` — the structural-test pattern to mirror (row counts, section spans, totals, no formulas).
* `frontend/src/app/(portal)/budget-planning/report/page.tsx` — `downloadWfpReportExcel`, `buildExportFilename` (client-side filename), and the "Export to Excel" button to add a PPMP equivalent to.
* `docs/v1.4.4/WFP_Excel_Export_Assessment.md` — the assessment behind the WFP export approach.

## Steps

1. `IPpmpReportExcelService`/`PpmpReportExcelService` (named distinctly, as `IWfpReportExcelService` was, to avoid colliding with the legacy `IWfpExcelService`). Build the sheet programmatically from `PpmpReportDto`: header block (PPMP, CY, END-USER/UNIT, per-fund "Charged to:"), the item-grained columns from §8 (Mode of Procurement dropped), interleaved section rows, account section totals (sum of items), a **separate table per fund source**, and the "Prepared by / NOTED BY" signatory block.
2. `GET /api/budget-planning/ppmp/report/export?officeId=&fiscalYear=&divisionId=` — sibling of the preview endpoint, same auth + `canAccessBudgetPlanning` gate + [RAL-136](https://linear.app/ralphoksiprojects/issue/RAL-136/wfp-report-preview-division-scope-for-non-finance-users-finance-sees) division clamp. Returns the `.xlsx` bytes.
3. Frontend: "Export to Excel" button on the PPMP report view (mirrors WFP); filename built **client-side** (`buildExportFilename` style — e.g. `PPMP{fiscalYear}_{officeCode}[_{divisionCode}]_yyyyMMddHHmmss.xlsx`).
4. Tests: `PpmpReportExcelServiceTests` against **structure** (row counts, section nesting, section totals = sum of items, per-fund tables, no formulas) — not styling, so they survive colour/width iteration (v1.4.4's did).

## Out of scope / Do NOT

* No Mode of Procurement column; no Summary sheet (per §7 Q12/Q13).
* Do NOT clone rows from a reference workbook — build programmatically.
* Do NOT re-implement the report projection — reuse `PpmpReportService`/`PpmpReportDto` from [RAL-183](https://linear.app/ralphoksiprojects/issue/RAL-183/ppmp-report-preview-backend-service-endpoint-item-grained-grid-on-the).
