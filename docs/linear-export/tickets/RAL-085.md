## Scope

### `DashboardCalendar.tsx` — color and interaction changes

**Updated event color map:**

| Event type / status | FullCalendar color |
| -- | -- |
| Office — Approved | `#16a34a` (green-600) — unchanged |
| Office — Pending (own) | `#f97316` (orange-500) — NEW |
| Office — Rejected (own) | `#ef4444` (red-500) — NEW |
| Personal | `#3b82f6` (blue-500) — unchanged |
| Holiday (PH) | `#f59e0b` (amber-500) — unchanged |

**Create event modal — non-admin submitting an Office event:**

* Button label: "Submit for Approval" (instead of "Create Event")
* After successful submit: show inline message "Your event has been submitted for admin approval." (replace the usual success toast for this path)

**Click on own Pending event:** open detail modal showing title, dates, and an amber "Awaiting admin approval" badge.

**Click on own Rejected event:** open detail modal showing title, dates, and a red notice box with the rejection reason text.

### `(portal)/dashboard/page.tsx` — pending count chips

**For non-admins (Staff / Observer / Office users):**

* Show a small chip near the calendar header: "N event(s) pending approval"
* Chip is only shown when count > 0
* Clicking the chip expands an inline list of their pending events (title + date)

**For Admin / SuperAdmin:**

* Show a chip: "N event(s) awaiting review" (amber background)
* Clicking opens `CalendarApprovalPanel` modal
* Chip hidden when count = 0

### New component: `CalendarApprovalPanel.tsx`

Location: `src/components/dashboard/CalendarApprovalPanel.tsx`

* Reuse `Modal` from `components/ui/Modal.tsx`
* Contains a `DataTable` listing all pending events:
  * Columns: Event Title · Submitted by · Start Date · Actions
  * Actions per row:
    * **Approve** (green text button) — single click, no confirmation; calls `PUT /api/dashboard/events/{id}/review` with `{ approved: true }`
    * **Reject** (red text button) — expands an inline reason input (required, max 500 chars) + "Confirm Reject" button; calls `PUT /api/dashboard/events/{id}/review` with `{ approved: false, rejectionReason }`
* After approve/reject: remove the row from DataTable, update the chip count
* Success/error feedback via `useToast()`

### API integration

ADD `lib/dashboard.ts` functions (or extend existing if file exists):

```ts
getPendingEvents(): Promise<PendingCalendarEvent[]>
reviewCalendarEvent(id: string, approved: boolean, rejectionReason?: string): Promise<CalendarEventResponse>
deleteCalendarEvent(id: string): Promise<void>
```

ADD types to `types/dashboard.ts`:

```ts
PendingCalendarEvent { id, title, description, startDate, endDate, isAllDay, createdByName, createdAt }
// CalendarEventResponse already exists — add: status: 'Pending' | 'Approved' | 'Rejected', rejectionReason?: string
```
