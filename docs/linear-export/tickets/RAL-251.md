# RAL-251 — Landing page: schema + resolution chain (user → division → office → fallback)

**V18-16** — plan: `docs/v1.8/Phase_Plan.md` §3.3. Foundation ticket for the whole landing-page cluster (V18-17…21, V18-28…31).

Requirement: a settable landing page — Main Dashboard, Inventory Dashboard, Budget Planning Dashboard, User Profile — with defaults per **office** and per **division** as well as per user (Ralph, 2026-08-20).

**Schema:** a `LandingPage` column on `users`, `divisions` and `offices`, all nullable.

⚠️ **Store a stable enum key** (`MainDashboard` / `InventoryDashboard` / `BudgetPlanningDashboard` / `Profile`) — **never a raw path**. Paths change; a stored `/inventory` or `/profile` rots silently and lands the user on a 404 months later.

**Resolution chain:**

```
user preference → division default → office default → role default
→ first permitted from an ordered list → /account
```

`/account` is the terminal fallback because it is the one page every authenticated user can always reach — which is why the existing office-user gate already falls back to it.

Every step must be **permission-checked**: a preference the user can no longer satisfy (flag revoked, division changed) falls through to the next step rather than producing a redirect loop.

**Done when:** the chain is one tested function in `PPDO.Application`, with cases for each level, for a revoked permission mid-chain, and for a user with nothing set anywhere.
