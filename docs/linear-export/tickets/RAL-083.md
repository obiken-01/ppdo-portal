# RAL-83 — DB + API: Announcements entity, CRUD, HTML sanitization

## Context

Part of v1.1.1 — Public Announcements feature. Admin/SuperAdmin create rich-text announcements in the portal; published ones display on the public landing page. This ticket covers the DB schema, domain entity, application service (with HTML sanitization), and all API endpoints.

See full spec: `docs/v1.1.1/v1.1.1_Requirements.md` §3B.

> 🌿 **Working branch:** create feature branch off `hotfix/1.1.1` — PR targets `hotfix/1.1.1`

---

## Scope

### EF Core migration: `AddAnnouncements`

New `announcements` table:

```sql
id              UNIQUEIDENTIFIER PK
title           NVARCHAR(200) NOT NULL
content         NVARCHAR(MAX) NOT NULL   -- sanitized HTML
status          INT NOT NULL DEFAULT 0   -- 0=Draft, 1=Published, 2=Archived
published_at    DATETIME2 NULL           -- set once on first Publish
created_by_id   UNIQUEIDENTIFIER FK → users (Restrict)
created_at      DATETIME2 NOT NULL
updated_at      DATETIME2 NOT NULL
```

Indexes: `status`, `published_at DESC`.

### Domain (`PPDO.Domain`)

* ADD `AnnouncementStatus` enum: `Draft = 0, Published = 1, Archived = 2`
* ADD `Announcement` entity (see spec §3B)
* ADD `AnnouncementConfiguration.cs` EF table mapping

### Application (`PPDO.Application`)

* ADD `IAnnouncementService` interface and `AnnouncementService` implementation
* ADD NuGet package `Ganss.Xss` — call `new HtmlSanitizer().Sanitize(content)` on every create/update before saving
* ADD DTOs: `AnnouncementPublicDto`, `AnnouncementDto`, `CreateAnnouncementDto`, `UpdateAnnouncementDto`

**Service methods (full spec in §3B):**

* `GetPublishedAsync()` — public, no auth — Published only, `PublishedAt DESC`
* `GetAllAsync(caller)` — Admin/SuperAdmin — all statuses
* `CreateAsync(caller, dto)` — creates as Draft; sanitize `content`
* `UpdateAsync(caller, id, dto)` — editable in Draft or Published; re-sanitize
* `PublishAsync(caller, id)` — sets `Published`, populates `PublishedAt` once
* `UnpublishAsync(caller, id)` — Published → Draft
* `ArchiveAsync(caller, id)` — Published → Archived
* `DeleteAsync(caller, id)` — hard delete Draft/Archived; `Conflict` if Published

**Permission check (all write methods):** role must be `Admin` or `SuperAdmin`. No new permission flag.

### Functions (`AnnouncementFunctions.cs`, new file)

| Method | Route | Auth | Notes |
| -- | -- | -- | -- |
| GET | `/api/announcements` | **Public** | No JWT check — declared as public endpoint in CLAUDE.md |
| GET | `/api/announcements/manage` | JWT, Admin/SuperAdmin | All statuses |
| POST | `/api/announcements` | JWT, Admin/SuperAdmin |  |
| PUT | `/api/announcements/{id}` | JWT, Admin/SuperAdmin |  |
| PUT | `/api/announcements/{id}/publish` | JWT, Admin/SuperAdmin |  |
| PUT | `/api/announcements/{id}/unpublish` | JWT, Admin/SuperAdmin |  |
| PUT | `/api/announcements/{id}/archive` | JWT, Admin/SuperAdmin |  |
| DELETE | `/api/announcements/{id}` | JWT, Admin/SuperAdmin |  |

Response shape: raw JSON array for GET public; `ApiResponse<T>` envelope for all others (matching config endpoints pattern).

Register `IAnnouncementService` in `Program.cs`.

## TDD Requirements

Write tests BEFORE implementing service logic. Cover:

* `CreateAsync` — creates Draft, sanitizes HTML (strip script tags)
* `PublishAsync` — Draft → Published, sets `PublishedAt`; re-publish does NOT update `PublishedAt`
* `UnpublishAsync` — Published → Draft
* `ArchiveAsync` — Published → Archived
* `DeleteAsync` — succeeds for Draft; succeeds for Archived; returns Conflict for Published
* `GetPublishedAsync` — returns only Published, sorted by `PublishedAt DESC`
* Permission: non-Admin/SuperAdmin caller → Forbidden on all write methods
* `NotFound` when ID doesn't exist
