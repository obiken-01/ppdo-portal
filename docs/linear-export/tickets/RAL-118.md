# RAL-118 — Config: Price Index page (procurement item catalogue)

> 🌿 **Working branch: **`release/1.4.0`. PRs target it, **not **`main`.
> 📌 Read the epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14) first, then `docs/v1.4/WFP_Rework_Requirements_Draft.md` §7.1 FULLY.
> ✔ **Updated 2026-07-07 (Ralph's answer to open question #9):** PPDO maintains this config, but critically — **Price Index data comes from GSO's own application**, currently downloaded as an Excel file (a future GSO API integration is a possibility, not in scope now). **This makes the CSV import path load-bearing, not a nice-to-have** — it is literally how GSO's export gets into the system. Test it against a realistic GSO-style export shape, not just round-tripping your own export.

## Why

Procurement expenditure entries (ticket #11) build their Total Appropriation from **line items** (name × qty × price) instead of an estimated lump sum. Users need to search a shared price catalogue when adding an item so prices are consistent and current, instead of retyping guessed prices every time.

## Scope

New config table + page, cloned from the existing Funding Source config pattern (simplest existing example: code/name/description/color, soft delete, CSV round-trip):

* `price_index_items`: `id, name, unit, unit_price, category (nullable), price_updated_at, is_active, created_at, updated_at`. Soft delete via `is_active` only, matching every other config table.
* API: `GET /api/config/price-index`, `GET .../csv`, `GET .../{id}`, `POST`, `POST .../csv`, `PUT .../{id}`, `DELETE .../{id}` — same shape as `ConfigFundingSourceFunctions.cs`, gated by `CanManageConfig`.
* `price_updated_at` auto-set to `UtcNow` whenever `unit_price` changes on save — surfaced in the config table and later in the item-search typeahead (ticket #11) so stale prices are visible, not silently trusted.
* Frontend page at `config/price-index`, cloned from `config/funding-sources/page.tsx` — table + create/edit modal + CSV import/export buttons.
* **✔ CSV import is the primary intended workflow, not a bonus feature** (per Ralph's 2026-07-07 answer) — PPDO downloads a price list from GSO's application and uploads it here. Make the import forgiving of column-name/order variance if practical, and surface clear row-level errors on a malformed upload (mirror `CsvImportResult`'s existing per-row error pattern).

## Acceptance Criteria

- [ ] `price_index_items` table + full CRUD API + CSV round-trip, cloned from the FundingSource pattern
- [ ] `price_updated_at` updates automatically whenever `unit_price` changes (create or update)
- [ ] Config page lists/creates/edits/soft-deletes items, shows `price_updated_at`
- [ ] Gated by `CanManageConfig` (same as other config pages)
- [ ] CSV import handles a bulk upload cleanly with per-row error reporting — this is PPDO's real workflow (downloading from GSO), not just a config-page nicety
