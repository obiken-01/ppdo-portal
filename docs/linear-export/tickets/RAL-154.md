# RAL-154 — Fund-source-scoped ceiling, allocation & WFP check (backend)

> Part of **v1.4.3 — Other Fund Source Ceiling & Allocation**. Child of the WFP Rework epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> Backend foundation — **must merge before the two frontend tickets (B, C)**.
> Working branch: `release/1.4.3`. Feature branch off `release/1.4.3`; PR targets `release/1.4.3` (NOT `main`).

## Why

Today ceiling/allocation is effectively single-fund: one `budget_ceilings` row per (office, FY) and one `division_allocations` row per (division, FY), with no fund-source dimension — that single pot behaves as General Fund. This ticket adds a `funding_source_id` dimension so every active fund source (driven by the `funding_sources` config table) has its own office ceiling, per-division allocation, and independent WFP over-allocation tracking.

## Steps

1. **Migration **`AddFundingSourceToAllocation` (single migration, safe sequence per §3.4):
   a. Add nullable `funding_source_id` to `budget_ceilings`, `division_allocations`, `wfp_division_allocation_ledger`.
   b. Backfill all existing rows in those three tables to the GF `funding_sources` row (resolve `@gfId` by `Code='GF'`; fail loudly if missing).
   c. Backfill `wfp_expenditures` (and legacy `wfp_expenditure_lines`) rows with null `funding_source_id` to GF: set `funding_source_id`, `funding_source_snapshot='GF'`, `funding_source_name_snapshot='General Fund'`.
   d. Alter the three `funding_source_id` columns to NOT NULL.
   e. Drop old unique indexes; add widened ones — ceiling: (office, FY, fund); allocation: (division, FY, fund); ledger key adds fund before wfp_record_id.
   f. Add FK `funding_source_id` → `funding_sources.id` (OnDelete Restrict) on all three.
2. **Domain + EF**: add `FundingSourceId` (+ nav) to the three entities; update the three IEntityTypeConfiguration classes (column mapping, unique index, FK) mirroring `BudgetCeilingConfiguration`.
3. **AllocationService**: add `fundingSourceId` to GetCeiling/UpsertCeiling/GetAllocations/UpsertAllocations; add `GetCeilingsAsync(officeId, fiscalYear)` returning all funds' ceilings; make Guard 1 + Guard 2 per fund source; `GetSetupStatusAsync` + `GetSetupOverviewAsync` key on GF only.
4. **AllocationDtos**: add `FundingSourceId` to write DTOs and `FundingSourceId` + `FundingSourceCode`/`Name` to read DTOs.
5. **WfpCeilingService**: keep the AIP check aggregate (do NOT fund-scope it); fund-scope the division-allocation check (GetDivisionAllocation by fund; ledger sums by fund); make `UpsertLedgerForActivityAsync` group the record's expenditures by FundingSourceId and upsert one ledger row per (division, FY, fund, wfp record); treat null-fund expenditures as GF; extend `WfpCeilingStatusDto` with a per-fund-source list (always include GF) filled in `GetStatusAsync`; fund-scope the finalize backstop.
6. **Ledger + expenditure repos**: add `fundingSourceId` to `SumUsedAmountAsync` and the ledger `FindAsync`; add a per-fund `SumTotalByWfpRecord` grouping as needed.
7. **Functions**: add `fundingSourceId` query param to ceiling/divisions GET+PUT; keep existing auth gates (CanManageAllocation for PUT, CanAccessBudgetPlanning for GET, non-finance own-division filter on GetDivisions). The `ceilings` endpoint returns the richer DTO.
