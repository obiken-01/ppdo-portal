# RAL-82 — DB: add approval fields to CalendarEvents

## Context

Part of v1.1.1 — Calendar Event Approval feature. The existing `CalendarEvents` table has no concept of approval status. This migration adds four nullable columns so non-admin Office event submissions can be queued for review before becoming visible to all users.

See full spec: `docs/v1.1.1/v1.1.1_Requirements.md` §2B.

> 🌿 **Working branch:** create feature branch off `hotfix/1.1.1` — PR targets `hotfix/1.1.1`

---

## Scope

### EF Core migration: `AddCalendarEventApproval`

ALTER the existing `calendar_events` table (no data loss):

| Column | Type | Default | Purpose |
| -- | -- | -- | -- |
| `status` | `int NOT NULL` | `1` (Approved) | `0=Pending, 1=Approved, 2=Rejected` — DEFAULT 1 keeps all existing rows as Approved |
| `reviewed_by_id` | `Guid? FK → Users (Restrict)` | NULL | Admin who reviewed |
| `reviewed_at` | `DateTime?` | NULL | When reviewed |
| `rejection_reason` | `nvarchar(500)?` | NULL | Shown to creator on rejection |

Add index on `status` for the pending-events query.

### Domain changes

In `PPDO.Domain`:

* ADD `CalendarEventStatus` enum (`Pending = 0, Approved = 1, Rejected = 2`) in `Enums/`
* UPDATE `CalendarEvent` entity: add `Status`, `ReviewedById`, `ReviewedAt`, `RejectionReason`, `ReviewedBy` nav prop
* UPDATE `CalendarEventConfiguration.cs`: map new columns; add FK constraint + index
