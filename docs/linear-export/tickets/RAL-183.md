# RAL-183 — PPMP Report — preview (backend service + endpoint + item-grained grid on the Report page)

The headline v1.5 deliverable. Add a **Project Procurement Management Plan (PPMP)** report to Budget Planning › Report, alongside WFP. **Preview first** (this ticket); the `.xlsx` export is a separate follow-up. Mirrors how WFP shipped ([RAL-132](https://linear.app/ralphoksiprojects/issue/RAL-132/budget-planning-add-report-page-wfp-preview-prelude-to-full-report) preview → v1.4.4 export).

**Read** `docs/v1.5/PPMP_Report_Findings.md` **FULLY — §8 is the locked build spec** (all design questions resolved 2026-07-27). Follow the province's own `ppmp admin2027.xlsx` layout.

## Read before writing code

* `docs/v1.5/PPMP_Report_Findings.md` — §8 (columns, rules, scope), §2 (the real form), §6 (Stock Card No. live-join decision).

* `backend/PPDO.Application/Services/WfpReportService.cs` (+ its interface + `WfpReportDto`) — the closest existing pattern: office/fiscalYear/division scoping, per-fund grouping, hierarchy rollups. Build `PpmpReportService` in its shape.
* `backend/PPDO.Domain/Entities/WfpProcurementItem.cs`, `WfpExpenditure.cs`, `WfpActivity.cs`, `AipActivity.cs`/`AipProject.cs`/`AipProgram.cs` — the data the report projects.

* `docs/PERFORMANCE_GUIDELINES.md` — query at the DB; **no** `GetAllAsync()`**-then-filter** (the v1.4.6 N+1 round is recent).

## Behaviour (from §8)

* **Row grain:** one row per `WfpProcurementItem`. Program → Project → Activity → Account render as interleaved **section rows** ("no unit price = section row"). Item rows carry Stock Card No., Short Category, Unit, Unit price, QTY, Est. Budget, and the four quarter qty/amount pairs (from `period_no` mapped to quarter).
* **Columns** (Mode of Procurement dropped): Item No. · AIP Ref Code · Description · Stock Card No. · Short Category · Unit · Unit price · QTY · Est. Budget · 1ST/1ST QRTR AMOUNT … 4TH/4TH QRTR AMOUNT · TOTAL.
* **Stock Card No. / Short Category:** live join via `PriceIndexItemId` (Q15) — blank for free-typed items; do NOT fuzzy-match on name.
* **Procurement only (Q8):** source only `WfpProcurementItem` rows. Skip `Nature = "Non-Procurement"`; a `"Combined"` expenditure contributes its procurement items only.
* **Account section total (Q11):** SUM of the item line totals beneath it, computed.
* **Fund-source grouping (Q4):** a separate table per fund source within one report — reuse the WFP `fundSourceReports` shape/rendering.
* **Scope (Q3):** division-scoped callers forced to their own division ([RAL-136](https://linear.app/ralphoksiprojects/issue/RAL-136/wfp-report-preview-division-scope-for-non-finance-users-finance-sees)); `CanManageAllocation`/`SuperAdmin` (and Admin — confirm) may pick a division OR office-consolidated (all divisions).
* **No** Mode of Procurement (Q12), **no** Summary sheet (Q13).

## Steps

1. **Application: **`PpmpReportDto` (per-fund tables → sections → item rows + computed totals) + `IPpmpReportService`/`PpmpReportService`, shaped like `WfpReportService` but item-grained and procurement-only. Slim DTO; aggregate server-side.
2. **Functions: **`GET /api/budget-planning/ppmp/report/preview?officeId=&fiscalYear=&divisionId=` — `AuthorizationLevel.Anonymous`, JWT via `_jwt.ValidateAsync`, `canAccessBudgetPlanning` gate + the [RAL-136](https://linear.app/ralphoksiprojects/issue/RAL-136/wfp-report-preview-division-scope-for-non-finance-users-finance-sees) division clamp, `{ data, error, message }` envelope. (Also a `…/offices` helper if the WFP report has one, or reuse it.)
3. **Frontend:** add `PPMP` to `REPORT_TYPES` (WFP stays default); on selection, call the PPMP preview and render the item-grained grid with per-fund tables. Reuse the existing selectors + division-lock. Loading state must not cause layout shift.
4. **TDD:** add `PpmpReportServiceTests` (procurement-only filter incl. Combined; section total = sum of items; per-fund grouping; quarter mapping; division vs office-consolidated scope).
