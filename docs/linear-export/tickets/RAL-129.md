# RAL-129 — WFP entry: make saved expenditures editable (+ delete)

> 🌿 **Working branch: **`release/1.4.0`. PR targets it, **not **`main`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).

## Why

Today the entry wizard only **appends** expenditures and shows an "added so far" list — there's no way to reopen a saved expenditure to correct it, or to remove one. Persisted, editable expenditures are the data foundation for the upcoming **PPMP report** feature, so each expenditure must round-trip cleanly through the DB (create → edit → delete).

## Files to read before coding

* `backend/PPDO.Functions/Functions/WfpExpenditureFunctions.cs` (GET list / GET by-id / **POST save is already "create or replace"** — confirm the replace path)
* `backend/PPDO.Application/Services/WfpExpenditureService.cs` + `IWfpExpenditureService.cs` (`SaveExpenditureAsync` — **verify whether** `SaveWfpExpenditureDto` **already carries an id for replace**; if it's create-only today, add the replace path that deletes old periods/items and rewrites atomically)
* `backend/PPDO.Application/DTOs/BudgetPlanning/WfpExpenditureDtos.cs`
* `backend/PPDO.Application/Services/WfpCeilingService.cs` ([RAL-122](https://linear.app/ralphoksiprojects/issue/RAL-122/wfp-division-allocation-ledger-aip-budgetallocation-ceiling-blocking) — an edit must re-run the ceiling checks, not bypass them)
* `frontend/src/app/(portal)/budget-planning/wfp/entry/page.tsx` (the "expenditures added" list + the Add Expenditure modal)
* `frontend/src/lib/wfp.ts` (add edit/delete calls); `frontend/src/components/ui/ConfirmDialog.tsx`

## Working branch

Create `feature/v1.4-ral-XXX-wfp-editable-expenditures` off `release/1.4.0`; PR against `release/1.4.0` (NOT main).

## TDD

Extend the WFP expenditure service tests: edit replaces cleanly (old periods/procurement items removed, no orphans), delete removes the expenditure + all children, and an edit that pushes over the AIP/division ceiling is still blocked ([RAL-122](https://linear.app/ralphoksiprojects/issue/RAL-122/wfp-division-allocation-ledger-aip-budgetallocation-ceiling-blocking)).

## Steps

1. **Backend edit:** confirm/complete `SaveExpenditureAsync` replace-by-id (delete old child periods/procurement items and rewrite in one transaction — mirror the AIP confirm-import single-`SaveChanges` pattern to avoid orphan rows).
2. **Backend delete:** add `DELETE /api/budget-planning/wfp/expenditures/{id}` (removes expenditure + child periods + procurement items), gated `CanAccessBudgetPlanning`.
3. **Ceiling re-validation** on edit (and recompute remaining after delete) via `WfpCeilingService`.
4. **Frontend:** each row in the "expenditures added" list gets **Edit** (reopens the Add Expenditure modal pre-filled from the by-id GET, saves via the replace path) and **Delete** (`ConfirmDialog`). Refresh the ceiling meters + "added so far" list after either.
