# RAL-90 — Perf: deduplicate /auth/me — shared current-user context

## Context

The v1.1.0 audit (2026-06-22) found the WFP page fires **four separate** `GET /api/auth/me` **requests** per load. Each averages ~463 ms warm, so ~1.85 s is spent re-resolving the same current user. Many other portal pages independently call `/auth/me` too — it's the standard per-page auth/permission check, but there is no shared cache so every component that needs the user re-fetches it.

> 🌿 **Working branch:** create feature branch off `hotfix/1.1.1` — PR targets `hotfix/1.1.1` (NOT main)

### Root cause

There is **no** `useAuth` **hook / current-user context**. Auth state lives in the `lib/auth.ts` singleton (token only). Every page/component that needs the user's role or permission flags calls `api.get('/auth/me')` directly in its own `useEffect`. On a page composed of several such components (WFP especially), that becomes N duplicate network calls for one logical value.

`grep` shows ~27 frontend files call `/auth/me`. The portal layout (`src/app/(portal)/layout.tsx`) already calls it once — that is the natural single source of truth.

### Approach

Introduce a `CurrentUserProvider` **+** `useCurrentUser()` **hook** that fetches `/auth/me` once and shares it via React context. Migrate the highest-duplication pages (WFP first) to consume the context instead of fetching directly. Lower-traffic pages can be migrated opportunistically.

---

## Frontend only — no backend change

1. **New **`src/components/auth/CurrentUserProvider.tsx`:
   * Context holding `{ user: MeResponse | null, loading: boolean, error: ... , refresh: () => Promise<void> }`.
   * Fetches `/auth/me` once on mount; exposes `useCurrentUser()`.
   * `refresh()` for when the profile changes (e.g. after `/account` edits in [RAL-88](https://linear.app/ralphoksiprojects/issue/RAL-88/user-profile-page-edit-profile-change-password)).
2. **Mount the provider** in `src/app/(portal)/layout.tsx` wrapping the portal shell, so every portal page shares one fetch. (The layout already fetches `/auth/me` — fold that into the provider.)
3. **Migrate WFP page** (`budget-planning/wfp/page.tsx`) and any of its child components to read `useCurrentUser()` instead of calling `/auth/me` — this is the page with 4× duplication, the primary win.
4. Migrate other obvious multi-fetch pages where straightforward (dashboard, config pages). Pages that legitimately need a fresh check (e.g. login flow in `(public)`) stay as-is — the provider is portal-scoped.

> ⚠️ Keep the existing **route-guard / redirect** behaviour intact. Several pages redirect office users or non-config users based on `/auth/me`; that logic must still run, just sourced from the context value.

## Acceptance Criteria

- [ ] WFP page issues **one **`/auth/me` request (verify in DevTools Network tab), down from four
- [ ] `useCurrentUser()` provides role + permission flags + officeId to any portal component
- [ ] All existing permission gates and office-user redirects still behave identically
- [ ] `refresh()` updates the shared user after a profile edit without a full reload
- [ ] tsc + `npm run build` pass
