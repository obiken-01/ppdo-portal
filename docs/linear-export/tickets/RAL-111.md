# RAL-111 — Bug: non-PPDO office user stuck in redirect loop between /dashboard and /budget-planning (prod)

## Symptom

Encountered in **production**. A newly-created **GSO** (non-PPDO, office) user logs in and the app gets stuck **bouncing between** `/dashboard` **and** `/budget-planning` — an infinite redirect loop that hangs the browser. The user cannot use the portal at all.

## Root cause

A structural redirect loop that triggers when an **office user (**`users.office_id` **set) lacks** `CanAccessBudgetPlanning` (e.g. no division assigned yet, or the division's `can_access_budget_planning` flag is off — so the flag resolves to `false`):

1. Login (`(public)/login/page.tsx`) routes office users (officeId set) → `/budget-planning`.
2. `budget-planning/page.tsx` calls `useMe((me) => me.canAccessBudgetPlanning)` with the **default** `redirectTo = "/dashboard"` (`lib/me-cache.ts`). Permission fails → `router.replace("/dashboard")`.
3. The portal layout's office-user gate (`(portal)/layout.tsx`) bounces any office user off `/dashboard` → `router.replace("/budget-planning")`.
4. → back to step 2, forever.

The loop only occurs for a **misconfigured office user** (one without budget-planning access), but the frontend hangs instead of failing gracefully.

## Fix (PR #92)

Break both sides of the loop so a no-access office user lands on a terminal page:

* **Layout office-user gate** → sends office users **lacking** budget-planning access to `/account` (a page they can always reach) instead of `/budget-planning`.
* **Budget Planning page** → on permission failure, redirects office users to `/account` (PPDO users still fall back to `/dashboard`).

## Follow-up (separate from the frontend fix)

The GSO user likely **should** have budget-planning access — verify office-user provisioning: assign the user a division whose `can_access_budget_planning` flag is on (or grant `OverrideCanAccessBudgetPlanning`). Consider whether newly-created office users should get budget-planning access by default. See `docs/v1.2/Allocation_Requirements.md` §6.

## Verification

* Office user **without** budget-planning access → lands on `/account`, no loop
* Office user **with** access → lands on `/budget-planning` normally
* PPDO user without budget-planning access → `/dashboard` (unchanged)
