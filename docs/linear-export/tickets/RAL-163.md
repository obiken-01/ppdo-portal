# RAL-163 — AllocationService: eliminate repeated full-table ceiling/allocation reloads (backend)

> 🌿 Working branch: `release/1.4.5`. PR targets `release/1.4.5` (NOT `main`). Child of epic [RAL-116](<https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14>).
> 📌 Backend-only. **Tier 1, item 1** of the performance audit — the single biggest Budget Planning finding.

## Why

`docs/Performance_Audit_2026-07-16.md` §1 found `AllocationService` repeatedly reloads the entire `budget_ceilings`/`division_allocations` tables via `GetAllAsync()` and then filters in memory, at 5 separate call sites — hit on nearly every Allocation-page call. This is exactly the anti-pattern `docs/PERFORMANCE_GUIDELINES.md` prohibits ("query at the database, not in memory").

## Files to read before writing code

* `docs/Performance_Audit_2026-07-16.md` §1 (Tier 1 section) — the finding this ticket implements
* `docs/PERFORMANCE_GUIDELINES.md` — the query-at-the-database rule + worked examples (`GetByDivisionAsync`/`GetByDateRangeAsync` templates)
* `backend/PPDO.Application/Services/AllocationService.cs:79-84, 121-141, 160-176, 339-395, 472-474` — every full-table reload site
* `backend/PPDO.Infrastructure/Repositories/` — existing ceiling/allocation repo method shapes to extend
* `backend/PPDO.Tests/Application/AllocationServiceTests.cs` — existing coverage to extend

## Working branch

`release/1.4.5`. Create `fix/v1.4.5-ral-163-allocation-service-scoped-queries` off `release/1.4.5` and open the PR against `release/1.4.5` (NOT `main`).

## TDD

Extend `AllocationServiceTests` with failing tests asserting the new scoped repo methods are called (`Times.Once`) instead of the full-table load, then implement.

## Steps

1. Add scoped repository methods (e.g. filter by officeId/fiscalYear/fundingSourceId via SQL `WHERE`) mirroring the `GetByDivisionAsync`/`GetByDateRangeAsync` template pattern from CLAUDE.md.
2. Replace each of the 5 full-table-reload call sites in `AllocationService.cs` with the new scoped method.
3. Before narrowing each call site, check whether any caller actually relies on the full unfiltered set as a side effect (e.g. a cross-office comparison) — don't assume all 5 sites are safe to scope identically.
4. Update/extend `AllocationServiceTests` mocks and assertions.

## Out of scope

Don't touch `WfpCeilingService`'s business logic — this ticket is query-shape only. Don't add fund-source-scoped pagination or any new UI — out of the audit's stated scope for this finding.
