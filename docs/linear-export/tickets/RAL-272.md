# RAL-272 — User Profile as a landing target (resolves to /account)

**V18-31** — plan: `docs/v1.8/Phase_Plan.md` §3.5. Depends on V18-21 ([RAL-252](https://linear.app/ralphoksiprojects/issue/RAL-252/drop-the-profile-stub-and-redirect-profile-account)) and V18-20 ([RAL-262](https://linear.app/ralphoksiprojects/issue/RAL-262/permission-aware-landing-selector-user-form-division-config-office)).

The fourth landing option: **User Profile →** `/account` (Ralph's decision, 2026-08-20).

Unlike the three dashboards this one is **always available** — `/account` is the one page every authenticated user can reach regardless of permissions, which is exactly why it is also the terminal fallback in the resolution chain (V18-16). So it needs no permission filter, and it is the guaranteed-safe answer when nothing else resolves.

Worth landing after V18-21 so the option never points at the "coming soon" stub.

**Done when:** selecting User Profile lands the user on `/account`, and it appears in the options list for every user including office users.
