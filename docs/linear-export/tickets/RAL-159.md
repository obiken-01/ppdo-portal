# RAL-159 — WFP Excel Export: backend template population + row-cloning engine

> 🌿 Working branch: `feature/v1.4.4-ral-159-wfp-excel-export-backend` off `release/1.4.4` (which branches off `main`, post-v1.4.3). PR targets `release/1.4.4`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> 📌 Backend, ClosedXML, medium-large. Main technical risk of v1.4.4 lives in this ticket.

## Why

PBO needs the WFP Report exported as an `.xlsx` that matches their official fixed-layout form (`WFP-NEW.xlsx`), not a generic export. `WfpReportDto` was already modelled on this exact form (its XML-doc comments reference "the WFP FINAL sheet"), so this is a **rendering** task off existing data, not new business logic. Full structure/column map/decisions: `docs/v1.4.4/WFP_Excel_Export_Assessment.md` — read it first.

## Build approach (revised 2026-07-16)

**Do NOT embed/clone rows out of** `WFP-NEW.xlsx`**.** Inspection found it's a *filled sample*, not a blank template — 293 merged ranges, and cell borders vary row-to-row within the same row-type (hand-touched around real sample data). Cloning styles from it would carry that noise into every export.

Instead: **build the sheet programmatically in ClosedXML** using a documented style catalog (constants below) applied per row-type, with vertical merges (activity/program/band ref columns spanning their block) **computed from the actual emitted row count** rather than copied from a fixed-size sample. Same visual output as the source form; the merge/style risk is designed out instead of mitigated.

Style catalog (extracted from `WFP-NEW.xlsx` inspection, confirmed 2026-07-16):

* Font: Arial Narrow 13 throughout (data cells), header row 7 bold.
* Fills: column header `#A8D08D`, sub-total row `#92D050`, activity/program grand-total `#FFFF00`/`#FFC000`, breakdown block `#C5E0B3`, grand-total row `#FFFF00`.
* Number format (all amount columns O–V): `_(* #,##0.00_);_(* \(#,##0.00\);_(* "-"??_);_(@_)`.
* Column widths (B–W, in Excel width units): B=37.8, C=1.0, E=31.5, F=12.5, G=15.2, H=14.3, I=13.8, J=18.7, K=13.8, L=20, M=20, N=45.8, O=17.5, P=17.7, Q=17.5, R=15.7, W=18.2.
* Borders: thin borders on cell boundaries per row-type; boundary rows (sub-total, grand-total) get top+bottom thin borders; interior data rows get left-only or none — see assessment doc for full breakdown if disputed.

## Scope

1. **Style catalog.** Define the row-type → style mapping above as C# constants/helpers in the new `WfpExcelService` (fills, fonts, borders, number formats, column widths).
2. **Computed vertical merges.** For each block (function-band label, program title, project title, activity ref+title, F–K placeholder columns), track the block's start/end row as rows are emitted, then call `MergeCells` over that range once the block is fully written — not copied from any template.
3. **Values only, no formulas.** The original form is formula-driven (`VLOOKUP` for account titles, `SUM` for totals/subtotals). **Confirmed with Ralph: overwrite every formula cell with the computed value instead** — write `Amounts.TotalAppropriation`, `NetAppropriation`, subtotals, grand-totals, and breakdown totals directly from `WfpReportDto` (it already holds all of them).
4. **Print/layout setup.** Landscape orientation. **Freeze panes removed** (Ralph confirmed fine to drop). **Column widths, cell fill colors, border layout, and merged-cell structure must be preserved exactly** — not optional, they're the form's visual identity and the main verification criteria for [RAL-160](https://linear.app/ralphoksiprojects/issue/RAL-160/wfp-excel-export-export-to-excel-button-live-verification). Repeat header rows per printed page and set print area per fund-source block if ClosedXML supports it cleanly; don't burn time forcing it if fragile.
5. **Per-fund repetition.** One form block per `WfpReportFundSourceDto` (the form's row-88 "restart" pattern). Land on **one sheet per fund source** unless that proves clearly harder than stacked blocks on one sheet — if so, fall back and note the deviation.
6. **F–K columns ship blank.** Do not populate Resources Needed / Responsible Person/Unit / Success Indicator / Means of Verification / Outcome Indicator / Target Beneficiaries. Do not add backend persistence for these fields — out of scope (Ralph's call, see assessment §4).
7. **New endpoint. **`IWfpExcelService.ExportWfpReport(WfpReportDto)` (new service, sibling pattern to `IWfpReportService`/`ExcelService.ExportPRReport`) + `GET /api/budget-planning/wfp/report/export` (sibling of the existing `WfpReportPreview` endpoint), same query params (office/fiscalYear/division), returns `.xlsx` bytes.
