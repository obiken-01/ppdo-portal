# RAL-192 — InventoryService scoped queries + list pagination

Full spec: `docs/v1.7/Mobile_And_Inventory_Findings.md` §3.2 + §3.3. Draft implementation prompt: `docs/v1.7/Ticket_Prompts.md` "RAL-F". Also read `docs/PERFORMANCE_GUIDELINES.md` and `docs/Performance_Audit_2026-07-16.md` §"Tier 3 — Inventory".

## Problem

`InventoryService.cs:78` and `:147` both load the **entire** item catalog via `_items.GetAllAsync()` just to resolve Description/ReorderQty for StockNos already known from `stockLevels`. `:63` similarly falls back to `_prs.GetAllAsync()` for admins with no division scope, then does five in-memory Count/Sum passes. No pagination exists on the PR, Delivery, or Items Master lists.

## Scope (TDD — extend `InventoryServiceTests.cs` with failing tests first)

1. Add `IItemMasterRepository.GetByStockNosAsync(IReadOnlyCollection<string>, ct)` — single IN-list query. Replace both `GetAllAsync()` + `ToDictionary` blocks (:78, :147), keyed only on StockNos present in `stockLevels`. [RAL-158](https://linear.app/ralphoksiprojects/issue/RAL-158/wfp-report-fix-n1-queries-in-report-generation-30s-load-100percent-cpu) is the in-repo precedent for this batching shape.
2. `GetStatsAsync` :61-71: replace the admin `GetAllAsync()` + in-memory Count/Sum with scoped repository aggregates (`CountAsync` per status, `SumAsync` for TotalAmount). Await sequentially — never `Task.WhenAll` over one `DbContext` (caused a prod 500 in `GetStatsAsync` previously, per CLAUDE.md).
3. Add server-side pagination (Skip/Take + total count) to the PR list, Delivery list, and Items Master list endpoints. Return slim DTOs — only the columns each grid renders. Update the corresponding frontend pages to page through.
4. Frontend cleanups in the same pass: replace the separate `/auth/me` fetch at `pr-report/page.tsx:236` with `useMe()`; batch the client-side N+1 at `receive-delivery/page.tsx:269-282`; replace full-page spinners with `LoadingState.tsx` skeletons on all 8 inventory pages.

If too large for one PR: split at step 3 (steps 1-2 = backend query fix, steps 3-4 = pagination + frontend) and say so in the PR rather than half-doing both.

Test cases: admin (null division) vs Staff (scoped) stats unchanged from before refactor; office user with no division still gets `EmptyStats` (SeeNothing); item-ledger date-range filter still restricts correctly; stock levels for a StockNo absent from catalog still fall back to StockNo-as-name and ReorderQty 0.

## Do NOT

Change the on-hand formula (`QtyDelivered - QtyDistributed`) — the future warehouse-stock ticket changes it to include opening balances and would conflict. Change low-stock `LogWarning` events. Change `DivisionScope` semantics.
