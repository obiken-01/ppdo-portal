# RAL-28 — Seed PermissionGroups and initial SuperAdmin user

Seed the 6 default PermissionGroups on first migration. These groups define the default feature access per division and must not be renamed — user creation logic references them by name.

**Groups to seed:**

| Name | Division | CanAccessInventory | CanAccessReports | CanManageUsers |
| -- | -- | -- | -- | -- |
| Admin Division Staff | Admin | true | true | false |
| Planning Staff | Planning | false | true | false |
| RM Staff | RM | false | true | false |
| MIS Staff | MIS | false | true | false |
| SPD Staff | SPD | false | true | false |
| Observer Default | null | false | false | false |

**Implementation:** Use EF Core `HasData()` in `AppDbContext.OnModelCreating()` or a dedicated `DbInitializer.cs` class called on app startup.

**Also seed one SuperAdmin user** for initial login:

* Email: `admin@ppdo.gov.ph` (placeholder — update on first deploy)
* Role: SuperAdmin
* Division: MIS
* Password: set a known default, force change on first login

**Reference:** `CLAUDE.md` → PermissionGroup Seed Data section
