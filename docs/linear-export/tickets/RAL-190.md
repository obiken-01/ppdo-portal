# RAL-190 — Inventory tables: mobile scroll + readable columns

**Blocked by:** portal shell drawer (v1.6.0) · **No backend changes**

Full spec: `docs/v1.7/Mobile_And_Inventory_Findings.md` §2.3. Draft implementation prompt: `docs/v1.7/Ticket_Prompts.md` "RAL-C".

## Problem

Every inventory table is already wrapped in `overflow-x-auto overflow-y-hidden`, but the table itself is `w-full` with no `min-w`, so it compresses columns to illegibility instead of triggering horizontal scroll. Affects all 8 inventory pages (`inventory/page.tsx`, `item-ledger`, `pr-register`, `pr-report`, `receive-delivery`, `distribution`, `items-master`, `create-pr`).

## Scope

1. Add a `min-w-[…]` to each table sized to its column count so `overflow-x-auto` actually engages. Keep `w-full` so wide screens are unchanged.
2. Reuse the WFP report's bottom-pinned scrollbar treatment ([RAL-147](https://linear.app/ralphoksiprojects/issue/RAL-147/wfp-report-page-single-bottom-pinned-scrollbar-printer-friendly-pdf)) to make horizontal scroll discoverable rather than inventing a new pattern.
3. `inventory/page.tsx` StatGroup's inner `flex gap-3` (no wrap today) needs `flex-wrap` or a responsive grid so stat cards reflow instead of overflowing.
4. Reduce page padding below `sm:` (`p-5` → `p-3`) consistently across all 8 pages.
5. Filter panels: confirm each `flex gap-4 flex-wrap` panel's inputs have a sane min-width at 375px.

## Do NOT

Change any table's column set, sorting, filtering, or data fetching. Do NOT convert to card layouts — scroll-and-legible first; card fallback is a possible follow-up.

## Manual test plan

- [ ] each of the 8 inventory pages at 375px: page body does not scroll horizontally
- [ ] each table scrolls horizontally within its own container, headers legible
- [ ] 1280px: all 8 pages pixel-identical to before this change
- [ ] stat cards on the Inventory Dashboard wrap rather than overflow
