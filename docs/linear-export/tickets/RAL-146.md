# RAL-146 — WFP entry: warn before discarding unsaved changes in the Add/Edit Expenditure modal

> 🌿 Bundled into PR #131 (`fix/v1.4.1-ral-145-function-band-auto-persist` → `main`) per Ralph's request — found while manually verifying [RAL-145](https://linear.app/ralphoksiprojects/issue/RAL-145/bug-function-band-default-core-never-persists-unless-the-dropdown-is) on that branch, fixed there rather than a separate branch. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> 📌 Found live 2026-07-13 by Ralph.

## Symptom

In the WFP entry wizard's Add/Edit Expenditure modal, an accidental click outside the modal or an accidental Esc keypress closes it immediately with no warning — silently discarding whatever the user had just typed (account, amounts, procurement items, etc.).

## Fix

`ExpenditureWizard` (`frontend/src/app/(portal)/budget-planning/wfp/entry/page.tsx`) now snapshots the form's starting values on mount (empty for Add, the existing expenditure's data for Edit) and compares the current values against that snapshot before actually closing. If nothing changed, close is instant (same as before). If something changed, a confirmation ("Discard unsaved changes? You have unsaved changes to this expenditure. Closing now will lose them." — Discard / Keep Editing) appears first, reusing the same `ConfirmDialog` pattern already used in this file for the "Switch Nature?" warning.

Covers all three close paths: backdrop click, Esc key, and the modal's × button (all route through `Modal`'s `onClose` prop) — plus the explicit "Cancel" button, for consistency.

The shared `Modal` component itself was intentionally left untouched — this is scoped entirely to `ExpenditureWizard`'s own close handler, so no other modal in the app (config forms, CSV upload preview, AIP manual entry, etc.) is affected.

## Test plan

- [X] Manual: open Add Expenditure, close immediately without entering anything (Esc / backdrop / Cancel) — closes with no warning
- [X] Manual: open Add Expenditure, type an amount, press Esc — "Discard unsaved changes?" appears
- [X] Manual: "Keep Editing" dismisses the confirmation only, the expenditure modal stays open with the typed value intact
- [X] Manual: "Discard" closes both the confirmation and the expenditure modal
