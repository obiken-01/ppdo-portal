# RAL-180 — AIP: copy an office's programs/activities from a prior fiscal year (carry-forward)

> 🌿 Working branch: `release/1.5.0` (off `main`). PR targets `release/1.5.0`, NOT `main` directly. Child of epic [RAL-59](<https://linear.app/ralphoksiprojects/issue/RAL-59/budget-planning-management-feature-ldip-aip-and-wfp-web-pages>).
> 📌 Created 2026-07-22 from Ralph's request: when starting a new fiscal year's AIP for an office (e.g. FY2028 for PPDO), the initial draft/layout of PPAs (Programs/Projects/Activities) should be copyable from a prior year's AIP (e.g. FY2027) instead of retyping everything via [RAL-62](<https://linear.app/ralphoksiprojects/issue/RAL-62/ui-aip-entry-form-createedit>)'s manual entry, one node at a time. Ralph was unsure whether *every* PPA should always carry forward, so the design lets the user pick which programs come across — Select All is the default (most years, most programs repeat).
> 📌 **Scope decisions confirmed with Ralph (2026-07-22):**
>
> * **Amounts carry over as-is** — PS/MOOE/CO copy from the source year as a starting estimate, not blank. Faster to trim an existing number down than type every activity's budget from scratch.
> * **Target record auto-creates if missing** — if no Draft AIP exists yet for the target fiscal year, this action creates one (Manual entry-source, mirrors [RAL-62](<https://linear.app/ralphoksiprojects/issue/RAL-62/ui-aip-entry-form-createedit>)'s `CreateManualRecordAsync`); if the target office isn't in it yet, this action adds it too (reusing [RAL-62](<https://linear.app/ralphoksiprojects/issue/RAL-62/ui-aip-entry-form-createedit>)'s `AddOfficeAsync` logic). One action does the whole thing — no separate "create the FY2028 shell first" step.
> * **No lineage tracking** — this is a clean, one-time copy. New Program/Project/Activity rows with fresh IDs; nothing links back to the FY2027 source (unlike [RAL-78](<https://linear.app/ralphoksiprojects/issue/RAL-78/feature-amendmentsupplemental-copy-flow-finalizeunlock-transitions>)'s `AipRecord.SourceId`, which tracks a same-year amendment chain — this is a different year, different mechanic, no schema needed for tracing).

## 0. Why this exists

Every fiscal year, most offices re-run largely the same programs (e.g. PPDO's core PPAs repeat year over year with updated budgets). Today the only ways to populate a new year's AIP are: upload a fresh `.xlsm` (PPDO-only, `CanUploadAip`), or manually re-type every Office → Program → Project → Activity by hand via [RAL-62](<https://linear.app/ralphoksiprojects/issue/RAL-62/ui-aip-entry-form-createedit>). Neither reuses last year's structure. This ticket adds a third path: **carry forward a prior year's programs into the new year, per office, with the user choosing which programs to bring across.**

## 1. Scope

Single office, cross-fiscal-year copy:

1. User picks a **target fiscal year** (e.g. 2028) and a **target office** (e.g. PPDO).
2. User picks a **source AIP record** to copy from (e.g. the FY2027 AIP) — must be a record that has that same office.
3. The source office's **programs** are listed as checkboxes (each program row shows its name + project/activity counts) — **Select All checked by default.**
4. On confirm, each selected program — and its full subtree (all projects, all activities, all fields including PS/MOOE/CO/CC/funding source) — is copied into the target office under the target fiscal year's AIP record.
5. Ref codes for the copied office reuse the exact same `RefCode`/`Name`/`Sector` as the source office — an office's ref code (`{sector prefix}-000-1-{Office.OfficeRefCode}`) is **year-independent**, so this is correct, not a coincidence. Copied Program/Project/Activity ref codes reuse their source ref codes too (the target office is guaranteed fresh/empty for anything not already copied, so there's no collision risk under normal use — see the collision guard below for the double-copy case).

## 2. Design sketch (reuses [RAL-62](https://linear.app/ralphoksiprojects/issue/RAL-62/ui-aip-entry-form-createedit) infrastructure heavily)

* New endpoint: `POST /api/budget-planning/aip/copy-office`

  ```json
  { "sourceOfficeId": 123, "targetFiscalYear": 2028, "programIds": [45, 46, 51] }
  ```

  `CanAccessBudgetPlanning`-gated (not `CanUploadAip` — same reasoning as [RAL-62](<https://linear.app/ralphoksiprojects/issue/RAL-62/ui-aip-entry-form-createedit>)/[RAL-179](<https://linear.app/ralphoksiprojects/issue/RAL-179/aip-inline-per-node-editing-for-existing-records-option-b-follow-up-to>): this isn't a new file import, office users should be able to do it too).
* Service method, roughly:
  1. Load `sourceOffice` (`AipRepository.GetOfficeByIdAsync`) — 404 if missing.
  2. **Find-or-create** the target `AipRecord` for `targetFiscalYear`: unlike [RAL-62](<https://linear.app/ralphoksiprojects/issue/RAL-62/ui-aip-entry-form-createedit>)'s `CreateManualRecordAsync` (which *rejects* if an active record already exists for the year), this needs the opposite — reuse the existing Draft/Manual record for that year if one exists, only create fresh if none does. Reject if an active record exists but is **not **`EntrySource == "Manual"` and `Status == "Draft"` (can't copy into an Upload-sourced or Final/Archived record — same status guard family as the rest of AIP).
  3. **Find-or-create** the target `AipOffice`: same `RefCode`/`Name`/`Sector` as `sourceOffice`; if an office with that exact `RefCode` already exists in the target record, reuse it (don't duplicate).
  4. For each `programId` in the request (must belong to `sourceOffice` — 400 if not): **collision guard** — if a program with that same `RefCode` already exists under the target office, reject the whole request with a clear "already copied" message listing the colliding ref codes (simple and safe; don't silently skip or silently overwrite).
  5. Deep-copy each selected program → all its projects → all their activities, preserving every field (RefCode, Name, FunctionBand/IsSynthetic/EsreCode/ImplementingOffice/StartDate/EndDate/ExpectedOutputs/FundingSourceId/FundingSourceSnapshot/Ps/Mooe/Co/Total/CcAdaptation/CcMitigation/CcTypologyCode) — everything **except **`Id` (new identity) and `IsCreation` (v1.4 WFP-entry-time flag, should reset to `false` on the copy, not carry over from last year's WFP data-entry decisions).
  6. Single `SaveChangesAsync` transaction; audit log as a Create on the target `AipRecord` (or per-program Creates — implementer's call, follow whichever existing audit granularity in `AipService` reads cleanest).
* Frontend: a "Copy from Previous FY" entry point — likely on `aip/new/page.tsx` as a third option alongside Upload/Manual Entry (a "Copy" tab), or as an action on `aip/detail/page.tsx` for an office that doesn't exist yet in the current year. Flow: pick target FY (if not already on a specific record) → pick source AIP (dropdown of existing AIP records, most recent first) → pick office (must exist in the chosen source) → checkbox list of that office's programs, **Select All pre-checked** → Confirm → land on the target record's detail page.

## 3. Open implementation questions for whoever builds this

* Where's the best entry point — a new tab in `aip/new/page.tsx`, or an action button on `aip/detail/page.tsx`? Either works with the same backend endpoint; pick whichever fits the existing IA better.
* Confirm the collision-guard behavior above (reject-with-list) is the right call versus silently skipping already-copied programs — re-verify with Ralph if it comes up during implementation.

## Acceptance Criteria

- [ ] `POST /api/budget-planning/aip/copy-office` — copies selected programs (with full project/activity subtrees) from a source office into a target-fiscal-year office
- [ ] Target `AipRecord` is found-or-created (Manual entry-source) for the target fiscal year; rejects if an active non-Manual or non-Draft record already exists for that year
- [ ] Target `AipOffice` is found-or-created, reusing the source office's exact RefCode/Name/Sector
- [ ] Copied Program/Project/Activity rows preserve every field from the source except `Id` (fresh identity) and `IsCreation` (resets to false)
- [ ] Collision guard: copying a program whose RefCode already exists under the target office is rejected with a clear error, not silently skipped/overwritten
- [ ] Only programs actually belonging to the given source office can be copied (400 otherwise)
- [ ] Frontend: office/program picker with per-program checkboxes, Select All checked by default
- [ ] TDD: `AipServiceTests.cs` covers find-vs-create record, find-vs-create office, full subtree copy fidelity, IsCreation reset, collision guard, wrong-office program rejection

## Out of scope

* Copying more than one office at a time (repeat the action per office).
* Any lineage/source tracking between the two years' rows (see the confirmed scope decision above).
* Program/project/activity-level *selective* copy below the program level (e.g. "copy this program but only 2 of its 5 activities") — a selected program always brings its whole subtree.
