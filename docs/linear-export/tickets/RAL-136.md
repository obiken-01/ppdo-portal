# RAL-136 — WFP Report preview: division-scope for non-finance users (finance sees consolidated, division users see own only)

> 🌿 Working branch: `release/1.4.2` (off `main`). PR targets `release/1.4.2`, not `main`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> 📌 Backend + frontend. Data-privacy fix + two UX additions per Ralph's follow-up note.

## Why

The WFP Report preview (`/budget-planning/report`, [RAL-132](https://linear.app/ralphoksiprojects/issue/RAL-132/budget-planning-add-report-page-wfp-preview-prelude-to-full-report)) merges every division's `WfpExpenditure` rows for an office into one consolidated report. That consolidated / all-division view should be **finance-officer-only**. A regular division user must only see the WFP report scoped to **their own division** — they should not see other divisions' figures.

## Current behavior

* `GET /api/budget-planning/wfp/report/preview?officeId=&fiscalYear=` → `WfpReportService` (`backend/PPDO.Application/Services/WfpReportService.cs`) walks the office's AIP hierarchy and merges `WfpExpenditure` across **all** divisions of the office. Gated only on `CanAccessBudgetPlanning`.
* `GET /api/budget-planning/wfp/report/offices?fiscalYear=` lists offices with any Draft/Final WFP.
* Frontend `frontend/src/app/(portal)/budget-planning/report/page.tsx` now defaults the office to PPDO (v1.4.1) but has no division concept at all.

## Scope

1. **Backend division-scoping**: when the caller lacks `CanManageAllocation` (i.e. not a finance officer), scope the preview to `caller.DivisionId` — the report must aggregate only that division's expenditures. Finance officers keep the full consolidated/all-division report by default. Mirror the pattern just used in `AllocationFunctions.GetDivisions` (v1.4.1 fix) — resolve the caller in the Function handler and pass an optional `divisionId` filter into `WfpReportService`.
2. **Division dropdown on the Report page** (new, per Ralph 2026-07-13): add a Division selector to `report/page.tsx`, alongside the existing Office/FY pickers. For finance officers: optional filter (blank = consolidated, all divisions; picking one narrows to that division). For division-scoped users: the dropdown is pre-set/locked to their own division (mirrors the WFP entry wizard's read-only division span for non-bypass users) — they can't pick another division's report. Division list should be scoped to the selected office (same `listDivisions({ active: "true", officeId })` pattern used elsewhere).
3. **"WFP Preview" link from the entry wizard** (new, per Ralph 2026-07-13): in `wfp/entry/page.tsx`, add a button/link (near the AIP/Office/Division selector row, or in the sticky header) that navigates to `/budget-planning/report` with the current AIP's fiscal year, office, and division pre-filled via query params (mirroring how `report/page.tsx` already reads `?officeId=` elsewhere in the app), and auto-triggers the preview generation on load (or shows a "generating…" state) rather than requiring the user to click "Generate Preview" again after landing.
4. Add/extend `WfpReportServiceTests.cs` — a division-scoped caller sees only their division's totals; a finance caller sees the consolidated totals.

## Out of scope

The report's layout/columns (already finalized in [RAL-132](https://linear.app/ralphoksiprojects/issue/RAL-132/budget-planning-add-report-page-wfp-preview-prelude-to-full-report)). Excel export (still deferred).
