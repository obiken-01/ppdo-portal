# RAL-187 — Responsive portal shell — sidebar drawer + hamburger

## Context

Mobile audit (docs/v1.7/Mobile_And_Inventory_Findings.md §2.1) found the portal

shell is unconditionally desktop: a fixed 224px sidebar with no breakpoint, no

drawer, no hamburger. At 375px width this leaves ~151px of usable content —

roughly 40% of the screen. Nothing else on the mobile audit is worth fixing

until this lands. Pulled forward from v1.7.0 into v1.6.0 because it's

cross-cutting (unblocks Budget Planning on mobile too, not just Inventory).

## Files to read first

* frontend/src/app/(portal)/layout.tsx (the shell: `flex h-screen ...

  overflow-hidden` at :206, plus the auth guard and print: variants that must

  survive unchanged)
* frontend/src/components/layout/Sidebar.tsx (the `w-56 shrink-0` aside at

  :121; collapsible Inventory/Config/Budget-Planning groups + auto-expand

  effects; user popup menu + click-outside handler at :64-72)
* frontend/src/components/layout/Topbar.tsx (`h-14 ... px-6` header — hamburger

  trigger goes here; user name already `hidden sm:block`)
* frontend/src/components/ui/Modal.tsx (existing overlay/backdrop conventions

  to match)

## Working branch

release/1.6.0. Create feature/v1.6.0-ral-A-responsive-portal-shell off

release/1.6.0, PR against release/1.6.0 (NOT main).

## Steps

1. Sidebar: static column at `lg:` and above; off-canvas drawer with backdrop

   below `lg:`. Preserve `print:hidden`.
2. Sidebar: accept `open`/`onClose` props. Close on route change, backdrop

   click, Escape. Do NOT auto-close at `lg:`.
3. Topbar: hamburger button visible only below `lg:`, left of the breadcrumb.

   Use an emoji glyph (☰) — this codebase uses emoji icons, not an icon

   library.
4. layout.tsx: hold `sidebarOpen` state, pass down. Keep every `print:`

   variant intact (WFP/PPMP report exports depend on them).
5. Touch targets in the drawer >= 44px tall (current nav links are ~40px).

## Manual test plan

- [ ] 375px: sidebar hidden, hamburger opens drawer over backdrop
- [ ] 375px: tapping a nav link navigates AND closes the drawer
- [ ] 375px: backdrop click and Escape both close it
- [ ] 1280px: layout pixel-identical to before this change
- [ ] Collapsible nav groups still auto-expand on route
- [ ] User popup menu still works in the drawer
- [ ] Print preview of a WFP report unchanged

## Do NOT

Change permission gating/isOfficeUser visibility rules, the auth guard, refresh

-retry logic, or route prefetch effect. This is layout-mechanics only.
