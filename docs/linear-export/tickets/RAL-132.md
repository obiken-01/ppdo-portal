# RAL-132 — Budget Planning: add Report page (WFP preview, prelude to full report generator)

> 🌿 **Working branch: **`release/1.4.0`. PR targets it, **not **`main`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> 📌 Layout reference: `WFP-NEW.xlsx`, sheet **"WFP FINAL"** (Ralph's reference workbook) — the exact column/row structure is inlined below so the implementer doesn't need the file, but it's the source of truth if anything here is ambiguous.

## Why

This is the prelude to a full WFP report generator (noted as not-yet-built in the epic). Before building export/print tooling, we need an on-screen **Report** page under Budget Planning where a user picks a report type, fiscal year, and office, and sees a read-only preview of that office's WFP laid out the way the province's actual WFP FINAL document is laid out. This ticket is preview-only — no Excel export.

## Scope

**Nav:** New page `frontend/src/app/(portal)/budget-planning/report/page.tsx`, route `/budget-planning/report`. Add a **"Report"** link in `Sidebar.tsx`'s Budget Planning section immediately below **WFP**, same pattern as the other links there.

**Selection controls:**

* Report type — dropdown, single option **"WFP"** for now (built to hold future types, not to route to them).
* Fiscal year — same selector pattern used elsewhere in Budget Planning.
* Office — populated **only** with offices that have at least a Draft WFP for the selected fiscal year (exclude "Not started"). Model this on `BudgetPlanningDashboardService`'s existing office-status construction (`WfpOfficeStatus`/`WfpOfficeStatusRank` — prefer Final, else most-recent Draft) rather than writing a new query from scratch.

**Report layout — mirrors the "WFP FINAL" sheet exactly:**

Header block: title `WORK AND FINANCIAL PLAN FY {year}`, `DEPARTMENT/OFFICE: {office name}`, `SOURCE OF FUND: GENERAL FUND`, reserve note (`Equiv. to 10% of Operational Expenses`).

Table columns, in order: `AIP REF CODE` · `PROGRAMS, PROJECTS AND ACTIVITIES` · `RESOURCES NEEDED` · `RESPONSIBLE PERSON/UNIT` · `SUCCESS INDICATOR` · `MEANS OF VERIFICATION` · `OUTCOME INDICATOR` · `TARGET BENEFICIARIES` · `NATURE OF IMPLEMENTATION` · `ACCOUNT CODE` · `OBJECT OF EXPENDITURE` · `TOTAL APPROPRIATION` · `RESERVED` · `NET APPROPRIATION` · `TIME FRAME` (1st/2nd/3rd/4th Quarter, 4 sub-columns) · `AMOUNT TO BE RELEASED` (annual net total).

Row grouping (top to bottom): **Function-band section header** (`CORE FUNCTIONS` / `STRATEGIC FUNCTIONS` / `SUPPORT FUNCTIONS`, from `AipProgram.FunctionBand`, [RAL-126](https://linear.app/ralphoksiprojects/issue/RAL-126/wfp-program-function-band-corestrategicsupport-activity-creation-flag)) → **Program row** (ref code + title, no account/amounts) → **Project row** (indented) → **Activity row** (indented further) → under each activity, three **expense-class subsections in fixed order** — `PERSONAL SERVICES` → `MAINTENANCE AND OTHER OPERATING EXPENSES` → `CAPITAL OUTLAY` — each listing its `WfpExpenditure` lines (Nature, Account Code, Object of Expenditure, Total Appropriation, Reserved, Net Appropriation, Q1–Q4, Amount to be Released) followed by a `SUB-TOTAL` row, and finally an `ACTIVITY GRAND TOTAL` row summing all three expense classes.

**⚠️ Open gap — flag before/while implementing:** the sheet's six narrative columns (`RESOURCES NEEDED`, `RESPONSIBLE PERSON/UNIT`, `SUCCESS INDICATOR`, `MEANS OF VERIFICATION`, `OUTCOME INDICATOR`, `TARGET BENEFICIARIES`) are **not captured anywhere in the current** `AipActivity` **entity** — it only has `ExpectedOutputs` and `ImplementingOffice`. Do not invent new fields/migrations for this in this ticket. Render those six columns blank/"—" for now (or map `ImplementingOffice` → Responsible Person/Unit and `ExpectedOutputs` → Outcome Indicator as a best-effort default — implementer's call, note the choice in the PR description), and flag to Ralph that capturing these properly is follow-up scope for whoever owns the AIP import.

**Backend — new read endpoint, since the existing one doesn't fit: **`GET /budget-planning/wfp/{id}/report` (`WfpService.ExportReportAsync`) is scoped to the **old classic **`WfpActivityDto`/`WfpExpenditureLineDto` model, to a **single (office, division) **`WfpRecord`, and returns binary Excel — none of that fits a JSON, office-wide, all-divisions, v1.4-model preview (`WfpRecord` is scoped by `AipRecordId + OfficeId + DivisionId`, so a full office report must merge across the office's divisions). Add a new read endpoint that walks the AIP hierarchy for the office's current AIP and assembles the nested JSON above, reusing `WfpExpenditureCalculator` for row math — do not re-derive totals by hand. Follow the pattern already established for Inventory's PR Report: a JSON preview endpoint separate from any future binary export endpoint (`PRReportService`/`IPRReportService` is the template).

**Performance:** per `docs/PERFORMANCE_GUIDELINES.md`, keep the response to only the columns the preview renders (no unused free-text fields), and sanity-check query cost for an office with many activities before shipping.

**Out of scope:** the Excel/.xlsx export of this report (preview only, this ticket); report types other than WFP; any change to how `WfpRecord` is scoped/stored per division; changing the existing classic-model `/wfp/{id}/report` export (it stays as-is for the old editor).

## Acceptance Criteria

- [ ] `/budget-planning/report` exists, linked from the sidebar directly below WFP
- [ ] Office dropdown only lists offices with a Draft-or-Final WFP for the selected fiscal year
- [ ] Selecting report type (WFP) + fiscal year + office renders a read-only preview matching the WFP FINAL sheet's column set and row grouping (function band → program → project → activity → expense-class subsections with sub-totals → activity grand total)
- [ ] Q1–Q4 and Amount to be Released figures match what `WfpExpenditureCalculator` computes for the same expenditures elsewhere in the app (no parallel computation logic)
- [ ] The report merges expenditures across all of the office's divisions for the selected AIP
- [ ] No Excel export exists yet for this new page (explicitly out of scope)
- [ ] The narrative-column gap (Resources Needed, etc.) is handled per the note above and called out in the PR description
