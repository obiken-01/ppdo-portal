# RAL-113 — LDIP file upload + activity-level fields (mirror AIP upload)

> 🌿 **Working branch:** confirm the current v1.3 integration branch (`release/1.3.0` if open, else `main`) before starting; PRs target that branch, **not **`main` directly.
> 📌 This ticket was found while testing [RAL-61](https://linear.app/ralphoksiprojects/issue/RAL-61/ui-ldip-entry-form-createedit) — PPDO confirmed LDIP, like AIP, needs a **file upload** path, not just manual program-name+budget entry. Reference file supplied: `LDIP 2027-2029 formatted.xlsx` (Occidental Mindoro, sheets `General`/`Social`/`Economic`/`Others`/`Program Description Form`/`AIP 2027`).

## 0. Why this exists

`docs/v1.3/RAL-61_LDIP_Entry_Form_Design.md` §1 explicitly says [RAL-61](https://linear.app/ralphoksiprojects/issue/RAL-61/ui-ldip-entry-form-createedit) **dropped** PS/MOOE/CO split, funding-source FK, expected outputs, implementing office, CC adaptation/mitigation/typology, and PDP/RDP/SDG/Sendai/NDRRM/NSP/PDPDFP alignment tags from scope because none were in the confirmed Penpot design at the time. The real LDIP source file carries all of that dropped detail — **at the activity level**, one row per activity, structured almost exactly like `aip_activities`. Today `ldip_programs` only has `ref_code / name / budget` (one lump ₱000 sum for the whole document period).

## 1. Column map of `LDIP 2027-2029 formatted.xlsx` (rows 8–9 headers; sheets General/Social/Economic/Others are structurally identical)

| # | Header | Notes |
| -- | -- | -- |
| 1 | AIP Reference Code | Program rows: 6 segments e.g. `1000-000-1-01-001`. Activity rows: 7 segments e.g. `1000-000-1-01-001-001` (program ref + `-NNN`) |
| 2 | Program/Project/Activity Description | Program rows hold the program name; activity rows hold the activity name |
| 3 | Implementing Office/Department | blank on program rows, populated on activity rows |
| 4 | Start Date | activity rows only — **stored as a bare year number (e.g.** `2026`**), not a month name** (AIP's `AipActivity.StartDate` stores month names like `"January"` — a real format difference, not a bug) |
| 5 | Completion Date | same as above (bare year, e.g. `2029`) |
| 6 | Expected Outputs | activity rows only, free text |
| 7 | Funding Source | activity rows only (e.g. "General Fund") |
| 8 | PS (Personal Services) | amount, ₱000 |
| 9 | MOOE | amount, ₱000 |
| 10 | CO (Capital Outlay) | amount, ₱000 |
| 11 | Total (=8+9+10) | program rows show the rollup of their activities; activity rows show their own total |
| 12 | CC Adaptation amount | ₱000 |
| 13 | CC Mitigation amount | ₱000 |
| 14 | CC Typology Code | text |
| 15 | PDP, RDP | text — **no AIP equivalent** |
| 16 | SDGs | text — **no AIP equivalent** |
| 17 | Sendai Framework | text — **no AIP equivalent** |
| 18 | NDRRM Plan | text — **no AIP equivalent** |
| 19 | NSP | text — **no AIP equivalent** |
| 20 | PDPDFP | text — **no AIP equivalent** |

Columns 1–14 map almost 1:1 to `AipActivity` (`backend/PPDO.Domain/Entities/AipActivity.cs`) minus `EsreCode` (not present in the LDIP file). Columns 15–20 are six new alignment/tagging columns unique to LDIP.

**Hierarchy is 3 levels, not 4**: Office (sector group) → Program → **Activity** directly — no Project level (AIP is Office → Program → Project → Activity). One new child table (`ldip_activities` under `ldip_programs`), not two.

**Out of scope**: `Program Description Form` sheet (Department/Program Title/Description/Mandates/Baseline/Sector Classification/Timeframe/Impact/Beneficiaries/Implementing units/Partner agency/Indicators/Estimated cost) — a separate one-row-per-program narrative form. Flag as an open question for PPDO; don't build now.

## 2. The AIP upload pattern to mirror (already shipped, [RAL-64](https://linear.app/ralphoksiprojects/issue/RAL-64/api-ldip-aip-and-wfp-crud-endpoints-net-9)/76)

Upload → parse-only preview → client stash → confirm → persist. No DB writes happen until Confirm.

* **Parser contract**: `backend/PPDO.Application/Services/IAipXlsmParser.cs` — `Parse(Stream) → Dictionary<string sector, List<ParsedAipOffice>>`, POCOs `ParsedAipOffice/Program/Project/Activity` (no IDs, in-memory only). Implementation `backend/PPDO.Infrastructure/Services/AipXlsmParser.cs` uses ClosedXML, detects sheets named `GENERAL_*`/`SOCIAL_*`/`ECONOMIC_*`/`OTHERS_*`.
  ⚠️ **The LDIP sample file uses plain sheet names** (`General`, `Social`, `Economic`, `Others`, no prefix/suffix) — confirm real PPDO-submitted files use the same plain names before hardcoding a sheet-match rule; don't assume AIP's `*_` convention.
* **Upload endpoint**: `backend/PPDO.Functions/Functions/AipFunctions.cs` — `POST /api/budget-planning/aip/upload?fiscalYear=`, raw `application/octet-stream` body, gated by `CanUploadAip` (PPDO-only), buffers `req.Body` into a `MemoryStream` first (Kestrel/isolated-worker disallows sync reads ClosedXML needs), loads active `FundingSource`s so the parser can flag unmatched funding-source text, calls `_aip.ParsePreviewAsync(...)` — pure parse, **no persistence**.
* **Confirm endpoint**: `POST /api/budget-planning/aip/confirm` — stateless; client echoes back the full parsed hierarchy from the preview response; `CanUploadAip` gated; persists as a Draft record.
* **Frontend flow**: `frontend/src/app/(portal)/budget-planning/aip/new/page.tsx` (Upload File / Manual Entry tabs, fiscal-year select, dropzone with `.xlsm` + 20MB validation, help panels) → stashes preview in `sessionStorage` → `frontend/src/app/(portal)/budget-planning/aip/import-preview/page.tsx` (stat tiles, sector breakdown, collapsible warnings, Confirm/Cancel) → `frontend/src/lib/aip.ts` (`uploadAipFile`, `confirmAipImport`, envelope unwrap + error helper).

### "Use Edit to view what was uploaded"

Feasible with existing routing: `frontend/src/app/(portal)/budget-planning/ldip/edit/page.tsx` already loads by `?id=` (query-param route — required since the app builds with `output: "export"`) and renders `LdipForm` pre-populated, read-only once Final. Gap: `LdipForm`'s "Created Programs" table shows program rows only — needs an expandable read-only **activity** sub-table under each program (implementing office, dates, outputs, funding source, PS/MOOE/CO, CC amounts + typology, 6 alignment columns).

## 3. Open decisions to confirm with PPDO before building

1. **Does manual "+ Add Program" also need activity-level fields**, or is upload the only path to activity detail (mirrors AIP, whose own Manual Entry tab is still disabled)? **Recommendation: upload-only** — keep manual entry Program-level only, avoid a huge manual multi-field form PPDO hasn't asked for.
2. **Permission gate**: reuse `CanUploadAip` (PPDO-only) for LDIP upload, or add a parallel `CanUploadLdip`? **Recommendation: reuse** `CanUploadAip` — same PPDO uploader role, avoids a 4th permission flag.
3. `ldip_programs.Budget`: become a computed rollup (`SUM(activities.Total)`) for uploaded records while staying manually-entered for Program-only manual records? **Recommendation: yes.**
4. `Program Description Form` **sheet**: separate ticket or additive nullable columns later? **Recommendation: punt, log as follow-up.**

- [ ] `LdipForm`'s "Created Programs" table shows read-only activity rows per program (the "view what was uploaded" requirement)
- [ ] `ldip_programs.Budget` populated as `SUM(activities.Total)` for uploaded programs
