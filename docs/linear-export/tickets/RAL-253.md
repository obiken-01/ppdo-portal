# RAL-253 — Password reset: schema for recovery answer + MustChangePassword + attempt throttle

**V18-22** — plan: `docs/v1.8/Phase_Plan.md` §3.4. Foundation for the password-reset cluster (V18-23…27). Flow settled by Ralph 2026-08-14 as **Option B**; the sub-decisions live inline in that same §3.4 table.

> ⚠️ **Corrected 2026-08-26.** This ticket previously cited `AIP_Requirements_Review.md` §2.6. **That document does not exist in the repo and never has** — do not go looking for it. `docs/v1.8/Phase_Plan.md` §3.4 is the authoritative source. The same dead reference was on [RAL-265](https://linear.app/ralphoksiprojects/issue/RAL-265/password-reset-backend-request-verify-endpoints-throttle-audit), [RAL-266](https://linear.app/ralphoksiprojects/issue/RAL-266/force-recovery-answer-setup-at-next-login-rollout-over-existing) and [RAL-267](https://linear.app/ralphoksiprojects/issue/RAL-267/tell-the-user-their-password-was-reset-and-when) and has been corrected there too.

Why Option B and not an emailed link: **there is no email infrastructure in this codebase at all** — no SMTP, no SendGrid, no `IEmailService` — and `User.Email` is optional and unverified while login is by username. Self-service therefore runs on a user-set recovery answer.

**Schema only in this ticket:**

* `users.RecoveryQuestionKey` — the key of a question chosen from a short fixed list (a fixed list, not free text: free-text questions invite unanswerable ones).
* `users.RecoveryAnswerHash` — hashed through the **same BCrypt path as a password**. It *is* a credential; it must never be readable by an admin, or Option B degrades into Option A with extra steps.
* `users.MustChangePassword` — also fixes the V18-26 finding for admin-initiated resets.
* An attempt counter or small attempts table, enough to lock reset attempts for an account after **5 failures in an hour** (without this, the answer is brute-forceable).

Naming: `users` is a legacy PascalCase table — new columns follow that table's existing convention, per `docs/NAMING_CONVENTIONS.md`.

**Done when:** the migration is in place with the fixed question list defined, and nothing yet reads it.
