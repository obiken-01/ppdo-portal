# RAL-235 — Adopt per-feature subfolders under PPDO.Application/Validators (mirror DTOs)

## Context

Follow-up from a Vertical Slice Architecture comparison (Medium article review). We're keeping Clean Architecture (Domain → Infrastructure → Application → Functions) — the layered, project-level split is intentional and enforced by project references. But VSA's feature-cohesion idea is worth borrowing cheaply where it costs nothing structurally.

`PPDO.Application/DTOs/` already has per-feature subfolders (`PurchaseRequest/`, `Items/`, `Delivery/`, `Distribution/`, `Inventory/`, `User/`, `Auth/`, etc.). `PPDO.Application/Validators/` is currently a flat empty scaffold (`.gitkeep` only — no `AbstractValidator` classes exist yet anywhere in the backend).

## Change

Restructure `PPDO.Application/Validators/` into per-feature subfolders mirroring the `DTOs/` feature folders, so the convention is established before the first validator is added:

```
Validators/
├── Announcements/
├── Auth/
├── BudgetPlanning/
├── Config/
├── Dashboard/
├── Delivery/
├── Distribution/
├── Inventory/
├── Item/
├── Items/
├── PurchaseRequest/
├── ResourceLinks/
├── User/
└── Users/
```

Document the convention in `CLAUDE.md` (Naming Conventions table) so future validators land in `Validators/<Feature>/CreateXDto Validator.cs` instead of a flat folder.

## Out of scope

* No actual `AbstractValidator` implementations — none exist yet.
* No changes to the Domain/Infrastructure/Functions layer split.
