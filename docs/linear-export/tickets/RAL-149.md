# RAL-149 — WFP Report print/PDF export: restore background colors + site-matching styling

> 🌿 Working branch: `release/1.4.2` (off `main`). PR targets `release/1.4.2`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> 📌 Frontend-only, small-medium.

## Why

Ralph shared a "Print / Save as PDF" export of the WFP Report page (`WORK AND FINANCIAL PLAN FY 2027`) and it renders completely plain/black-and-white — none of the on-screen row shading (fund-source section highlights, program/project/activity grand-total rows, the section-closing breakdown block) survives into the PDF, and there's no header branding/color at all. This is a direct reversal request: during [RAL-147](https://linear.app/ralphoksiprojects/issue/RAL-147/wfp-report-page-single-bottom-pinned-scrollbar-printer-friendly-pdf) a `print-color-adjust: exact` rule was added to force background colors into print output, but Ralph asked to cut it mid-session ("no dont apply it, cross out my last command") — at the time the ask was purely "one scrollbar, printer-friendly," not "match the site's look." Now that the PDF export is actually being used, Ralph wants the backgrounds/styling back.

## Scope

1. Re-add `print-color-adjust: exact` / `-webkit-print-color-adjust: exact` (or the Tailwind `print:` equivalent) to the WFP Report print stylesheet (`frontend/src/app/(portal)/budget-planning/report/page.tsx`) so the existing row-shading classes (`bg-green-50/100/200`, `bg-slate-800/100`, etc., already gated by `print:break-inside-avoid` from [RAL-147](https://linear.app/ralphoksiprojects/issue/RAL-147/wfp-report-page-single-bottom-pinned-scrollbar-printer-friendly-pdf)) actually paint in the printed/PDF output.
2. Review the exported PDF against the live on-screen report and the portal's design tokens (`tailwind.config.ts` PPDO palette) — add whatever header/section styling is needed so the printed report reads as "from this website," not a bare data table (e.g. section headers, fund-source block dividers, PPDO green accents on totals).
3. Verify print output in at least Chrome's print-to-PDF (matches what Ralph's screenshot was produced with) — background colors are notoriously easy to still get stripped by other print-preview engines even with `print-color-adjust: exact` set, so a real print-to-PDF check is required, not just DOM inspection.

## Out of scope

The single bottom-pinned horizontal scrollbar behavior and page-break rules from [RAL-147](https://linear.app/ralphoksiprojects/issue/RAL-147/wfp-report-page-single-bottom-pinned-scrollbar-printer-friendly-pdf) — those are already correct and should not be touched. The classic `/wfp/{id}/report` Excel export (old model) — untouched, unrelated code path.
