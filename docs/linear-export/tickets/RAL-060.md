# RAL-60 — Budget Planning dashboard — office-scoped readiness/progress hub (replaces Office Selection page)

> 🌿 **Working branch (v1.3): **`release/1.3.0` (off `main` once v1.2.0 is prod baseline); PRs target `release/1.3.0`, **not **`main`.
> 📌 Read the **Alignment update** on the epic [RAL-59](<https://linear.app/ralphoksiprojects/issue/RAL-59>) first.

## 🔄 Scope change (2026-07-01) — no separate Office Selection page

The original "Office Selection page" is **dropped**: it duplicated the existing **Budget Planning Dashboard** ([RAL-80](https://linear.app/ralphoksiprojects/issue/RAL-80/ui-budget-planning-dashboard), `frontend/src/app/(portal)/budget-planning/page.tsx`), which already provides the FY selector, office selector (PPDO) / locked office (office user), LDIP/AIP/WFP nav, doc counts, WFP-status-by-office table, and recent activity.

Instead, **enhance that dashboard into an office-scoped readiness/progress hub** so a user can see, for one office, exactly where that office is in the budget pipeline: **Allocation setup → LDIP → AIP → WFP**.

## Goal

For the **selected office** (PPDO picks any; office user is locked to their own), surface the pipeline state at a glance:

1. **Allocation setup (v1.2)** — the "setup-complete" triad from `docs/v1.2/Allocation_Requirements.md` §4:
   * **Budget ceiling** set for the office + FY? (show amount / "not set")
   * **Division allocations** done? (show `allocated ₱X of ₱Y · remaining ₱Z`, flag over-allocation)
   * **PPAs assigned to divisions**? (show `assigned / unassigned` program counts — unassigned PPAs are invisible in WFP, so finance must see them)
   * Link to `/budget-planning/allocation`. Data source: `AllocationService` (`budget_ceilings`, `division_allocations`, `program_divisions`).
2. **LDIP** — are programs being created for this office, and **how many** (+ Draft/Final/Archived breakdown). Link to `/budget-planning/ldip`.
3. **AIP** — is an AIP **already created** for this office, and the **number of PPAs** (activities) created for it. Link to `/budget-planning/aip`.
4. **WFP** — creation in progress / finished per office. ✅ **Already present** via `wfpByOffice` (`WfpOfficeStatus`: Draft / Final / Not started) — reuse it; confirm it reads correctly per office (and per division, v1.2).
5. **Recent activity** — top 10. ✅ **Already** `TOP(10)` in the backend (`BudgetPlanningDashboardService.GetRecentActivityAsync` → `GetRecentAsync(10, …)`); just confirm the UI renders ≤10 and is office-scoped.

## ⚠️ Backend gap — dashboard DTO must become office-scoped

Current `PlanningDashboardDto` (`backend/PPDO.Application/DTOs/BudgetPlanning/PlanningDashboardDtos.cs`) returns **global** LDIP/AIP totals with a status breakdown and **no allocation-setup status**. Extend the endpoint/service (TDD, `BudgetPlanningDashboardService`) to add, **scoped to a given** `officeId` **+ FY**:

* allocation-setup status (ceiling set? allocated vs ceiling; assigned vs unassigned PPA counts),
* per-office **LDIP program count** (+ breakdown),
* per-office **AIP presence + PPA/activity count**.
  WFP-by-office already exists.

## 🔄 Alignment notes (2026-07-01)

* **Pick once, stay scoped:** wire the selected `officeId` into the LDIP/AIP/WFP nav links so the office choice carries into those flows (today the nav points at unscoped lists).
* **Money units:** ceilings/allocations are in **pesos** (NOT thousands — only AIP totals are thousands; `Allocation_Requirements.md` §7). Display with `formatMoney` / `MoneyInput`; do **not** ×1000 the allocation figures.
* **Division scope (v1.2):** WFP is per-division; the WFP indicator should respect the viewer's division scope (Staff → own division; Admin/finance → all). Allocation-setup indicators are most relevant to PPDO/finance (`CanManageAllocation`); for a plain office Staff, a simple "your division: ready / setup incomplete" hint is enough.
* **Stale copy fix:** replace the "Visitor view" label in the dashboard (page.tsx ~line 176) with "Office view" — "Visitor" was retired in v1.1.
* Reuse `DataTable`/`Modal`/`Toast`/`MoneyInput` from `components/ui/`; flat design; gate on `CanAccessBudgetPlanning`. TDD for the backend service extension.
