# RAL-94 — Perf: defer WFP config loads until needed (48 KB accounts on mount)

## Context

Lighthouse audit of the live WFP page (2026-06-22, no AIP selected) showed the page eagerly fetches all config data on mount — before the user picks anything. The network waterfall: `/api/config/accounts?active=true` = **48.9 KB** (all 143 accounts), plus `/api/config/offices` and `/api/config/funding-sources`, all fired in the initial-load `Promise.all`. Accounts and funding sources aren't actually used until an AIP+office is selected (funding) or the expenditure popup opens (accounts), so ~50 KB + extra round-trips are loaded for the initial render that doesn't need them.

> 🌿 **Working branch:** create feature branch off `hotfix/1.1.1` — PR targets `hotfix/1.1.1` (NOT main)

### Root cause

`frontend/src/app/(portal)/budget-planning/wfp/page.tsx`, **Effect A** (~line 639) runs on auth and loads four lists at once:

```ts
Promise.all([
  listAip(),                          // needed now — populates the AIP selector
  listOffices({ active: "true" }),    // needed now — populates the office selector
  listAccounts({ active: "true" }),   // 48 KB — only used in the expenditure popup
  listFundingSources({ active: "true" }), // only used once an AIP+office is selected
])
```

`accounts` feeds the `AccountCombobox` inside the per-activity expenditure popup. `fundingSources` is used by `resolveDefaultFundingSourceId` when the AIP detail loads (**Effect B**, ~line 674) and in the popup. Neither is needed for the initial two-selector view.

### Approach

Keep `listAip` + `listOffices` in the mount effect (they populate the always-visible selectors). Move `listAccounts` and `listFundingSources` to load when they're first needed — fundingSources alongside the AIP-detail load in Effect B (gated on `selectedAipId` + `selectedOfficeId`), accounts on first expenditure-popup open (or also in Effect B if simpler). Guard against duplicate loads (don't refetch if already populated).

---

## Frontend only — no backend change

1. **Effect A**: reduce the mount `Promise.all` to `listAip()` + `listOffices({ active: "true" })` only.
2. **Effect B** (AIP+office selected): also load `listFundingSources({ active: "true" })` here if `fundingSources` is empty — it's required by `resolveDefaultFundingSourceId` when the AIP detail arrives. Make sure the default-funding-source resolution still runs after both detail and funding sources are present.
3. **Accounts**: load `listAccounts({ active: "true" })` lazily on first expenditure-popup open (cache in state so it loads once), or in Effect B if that's cleaner. Verify the `AccountCombobox` still works.
4. Add simple "already loaded" guards so selectors/popups don't refetch on every interaction.

> ⚠️ Preserve current behaviour: AIP/office selectors populate immediately; default funding source still auto-resolves per activity; offline localStorage draft buffer and finalize/unlock flow unchanged.

## Acceptance Criteria

- [ ] Initial WFP load (no AIP selected) issues **only **`listAip` + `listOffices` — no accounts/funding-sources request (verify in DevTools Network tab)

- [ ] Opening the expenditure popup has accounts available in the `AccountCombobox` (lazy-loaded once)
