## 🔄 Alignment update — 2026-07-01 (still applies; read before implementing)

These tickets were authored in the **v1.1** cycle (June 9–10). Since then v1.1 ([RAL-70](https://linear.app/ralphoksiprojects/issue/RAL-70/api-config-crud-endpoints-csv-uploaddownload) config, [RAL-81](https://linear.app/ralphoksiprojects/issue/RAL-81/permissions-budget-planning-config-permission-flags-and-office) access model), v1.1.1, and v1.2 (divisions, allocation, `MoneyInput`, per-division WFP, [RAL-58](https://linear.app/ralphoksiprojects/issue/RAL-58/v12-security-hardening-auth-layer-rate-limiting-httponly-refresh) security) shipped. The deltas below apply to **every** child ticket and supersede any conflicting text further down.

**Access model (was "Visitor/Observer" — now flag-based,** [RAL-81](https://linear.app/ralphoksiprojects/issue/RAL-81/permissions-budget-planning-config-permission-flags-and-office) **+ v1.2):**

* Three feature flags gate Budget Planning: `CanAccessBudgetPlanning`, `CanUploadAip` (PPDO-only), `CanManageConfig`. For Staff they resolve from the user's **division row** (`divisions.can_*`) with per-user `OverrideCan*` taking precedence; SuperAdmin/Admin default all-true.
* `users.office_id` is the office discriminator: `null` = PPDO (all offices), set = office user (own office only). Office users are redirected to `/budget-planning` (their only feature).
* Roles are **SuperAdmin / Admin / Staff**. **Observer role, **`PermissionGroup`**, and the **`Division` **enum were all retired in v1.2.** Division is now a configurable per-office `divisions` table.
* Authoritative: `docs/v1.1/User_Roles_Permissions.md` + `docs/v1.2/Allocation_Requirements.md` §5–6.

**Status workflow:** Draft (editable) → Final (locked, read-only) → Archived (superseded). Transitions are **Finalize** + **admin unlock** — there is **no "Submit"/"Approve"** step. See `docs/v1.1/DB_Model.md` notes 9 & 11.

**Money & units:** AIP amounts are stored in **thousands** → multiply **×1000** for all display/validation (page layer only). Ceilings/allocations are in **pesos**. Use the shared `MoneyInput` component + `formatMoney`/`parseMoney` util for every money field.

**Reference data is already built: **`offices`, `funding_sources`, and `accounts` config tables + CRUD pages exist. Forms must pull from these — **Funding Source = FK to **`funding_sources` (store code snapshot); **PS/MOOE/CO is derived from **`accounts.account_number` **prefix**, not free-typed categories.

**Divisions (v1.2):** WFP is now **per-division**; a Staff user sees only their division's PPAs. Allocation lives on the finance-only `/budget-planning/allocation` page. LDIP/AIP remain office-scoped.

**UI standard:** reuse `Modal`/`MessageDialog`/`Toast`/`DataTable`/CSV buttons from `components/ui/`; flat design (no rounded corners); TDD for backend (failing xUnit first).

## AIP Reference Code Format

`SSSS-000-L-CC-OOO` (office, 5-seg) → `-PPP` (program, 6) → `-XXX` (project, 7) → `-YYY` (activity, 8)

* SSSS = Sector (1000/3000/8000/9000) · L = LGU type (1=Province) · CC = Office category (01/02/03) · OOO = Office code · then PPA segments per level.
