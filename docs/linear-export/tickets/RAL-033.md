# RAL-33 — Add structured ILogger<T> business event logging to Application services

Add structured `ILogger<T>` business event logging to all Application services. This runs after the services themselves are implemented in v1.0 — one pass through each service to add the correct log statements.

**Logging pattern — always use named parameters, never string interpolation:**

```csharp
// ✅ Correct
_logger.LogInformation("PR submitted. PRNo: {PRNo}, Division: {Division}, By: {UserId}", pr.PRNo, pr.Division, userId);

// ❌ Wrong
_logger.LogInformation($"PR submitted: {pr.PRNo}");
```

**LogInformation — business events:**

| Service | Event | Parameters |
| -- | -- | -- |
| PurchaseRequestService | PR submitted | PRNo, Division, UserId |
| PurchaseRequestService | PR status changed | PRNo, OldStatus, NewStatus |
| DeliveryService | Delivery received | DeliveryRef, PRNo, UserId |
| DeliveryService | Distribution recorded | IssueRef, Division, QtyIssued |
| UserService | User created | UserId, Role, Division |
| UserService | User deactivated | UserId, By (admin UserId) |
| AuthService | Login success | UserId |

**LogWarning — alert events:**

| Service | Event | Parameters |
| -- | -- | -- |
| ItemService | Low stock alert | StockNo, ItemName, RemainingQty, ReorderQty |
| AuthService | Login failed | Email only — never log passwords |
| Any service | Permission denied | UserId, Feature attempted |

**LogError — failure events:**
All caught exceptions in Application services — `ex` as first parameter, relevant context second.

**Never log:** passwords, JWT tokens, full request bodies, sensitive PII beyond UserId.

**Reference:** `CLAUDE.md` → Logging section (Architecture Rules)
