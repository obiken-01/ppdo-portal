# RAL-259 — Division config: default landing page + review the flag set

**V18-13** — plan: `docs/v1.8/Phase_Plan.md` §3.2. Depends on V18-16 ([RAL-251](https://linear.app/ralphoksiprojects/issue/RAL-251/landing-page-schema-resolution-chain-user-division-office-fallback)) for the schema and the enum.

Surface the division-level default landing page on the Division config page (`config/divisions`) — the second link in the resolution chain, and the one that does the most work in practice: PPDO's Admin division wants Inventory, the planning divisions want Budget Planning.

**Scope:**

* The `LandingPage` field on the division form, using the permission-aware selector from V18-20. ⚠️ Filter the options by that **division's** own `Can*` flags, not the editing admin's — a division whose `CanAccessInventory` is false must not be settable to the Inventory Dashboard.
* Include it in the CSV round-trip if that page has one (see [RAL-239](https://linear.app/ralphoksiprojects/issue/RAL-239/division-config-make-both-code-and-name-editable-via-a-code-keyed) for the code-keyed upsert this page uses).
* Second, smaller task: **review the division flag set** now that reviewer / LFC / PBO ceiling are per-user grants rather than division defaults. Confirm nothing on `Division` has become redundant, and that the split (division = defaults, user = individual grants) is still stated correctly in the entity's XML docs.
