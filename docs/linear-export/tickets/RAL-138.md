# RAL-138 — Price Index config: add "days-enabled" flag; gate the procurement Days field on it

> 🌿 Working branch: `release/1.4.2` (off `main`). PR targets `release/1.4.2`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> 📌 Backend (new column + migration + CSV round-trip + config UI) + frontend (conditional Days field).
> ✅ Resolved 2026-07-13: the flag lives on the **Price Index item** (NOT the Account). Confirmed by Ralph.

## Why

The "number of days" field on procurement line items ([RAL-127](https://linear.app/ralphoksiprojects/issue/RAL-127/wfp-add-number-of-days-to-procurement-line-items)) multiplies into the line total (`qty × unitPrice × days`). Division heads requested it specifically for **venue / food / accommodation**-type items, where a multi-day meeting's cost scales by the number of days. For every other item, the Days field is noise. We want Days to be **enabled only for items that actually use it**, driven by a flag on the Price Index item rather than shown everywhere.

## Scope

1. **Config column**: add a boolean flag to `PriceIndexItem` (`backend/PPDO.Domain/Entities/PriceIndexItem.cs`) — e.g. `DaysEnabled` (snake_case `days_enabled` per naming conventions). Migration in `PPDO.Infrastructure/Data/Migrations/`; map in `PriceIndexItemConfiguration.cs`.
2. **CSV round-trip**: include the new flag in the Price Index CSV import/export (the primary ingestion path per the entity's doc comment) + a round-trip test.
3. **Config UI**: surface the flag in the Price Index config page (add/edit + grid column).
4. **WFP entry**: in the procurement line-item entry (`frontend/src/components/wfp/WfpProcurementItemTable.tsx`), enable/disable the Days input based on the **picked price-index item's **`DaysEnabled` flag (default Days = 1, and don't let a disabled row contribute a days multiplier). The item is snapshotted at pick time ([RAL-125](https://linear.app/ralphoksiprojects/issue/RAL-125/wfp-entry-ui-procurement-line-item-entry-price-index-presets)), so decide whether to snapshot the flag too or resolve it live — snapshotting keeps a saved line stable if the flag is later toggled in config.

## Out of scope

Changing how Days multiplies into the total (already correct from [RAL-127](https://linear.app/ralphoksiprojects/issue/RAL-127/wfp-add-number-of-days-to-procurement-line-items)). Any flag on the Account entity — the gate keys off the selected Price Index item, not the expense account.
