# RAL-161 — Budget Planning Dashboard rework: PPDO-scoped queries + per-division/fund data (backend)

> 🌿 Working branch: `release/1.4.5` (branched off `release/1.4.4`, which has not yet merged to `main` — has [RAL-159](https://linear.app/ralphoksiprojects/issue/RAL-159/wfp-excel-export-backend-template-population-row-cloning-engine)/160's WFP Excel export work). PR targets `release/1.4.5`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> 📌 Backend, medium-large. Rewrites `BudgetPlanningDashboardService` in place — no new page.

## Why

Budget Planning is effectively PPDO-only in practice, but the Dashboard still queries/renders as if every office matters equally, and does so inefficiently: `GetDashboardAsync` does 4 unfiltered `GetAllAsync()` full-table loads (`ldip_records`, `aip_records`, `wfp_records`, `offices`) then filters in memory, plus a call into `AllocationService.GetSetupOverviewAsync` which does 4 more — 8 unfiltered full-table scans per Dashboard page load. Worse, none of the three Dashboard endpoints (`GetDashboard`/`GetActivity`/`GetOfficeDashboard`) actually enforce office/division scoping server-side — they check the `CanAccessBudgetPlanning` permission and then discard the resolved caller entirely. Full findings + plan: `docs/v1.4.4/Budget_Planning_PPDO_Scoping_Dashboard_Optimization_Assessment.md` §2 and §4 — **read §4 first**, it has the exact method signatures this ticket implements.

## Scope

1. **New** `IOfficeRepository : IRepository<Office>` (`GetByIdAsync(int)`, `GetByCodeAsync(string)`) + EF implementation — `Office` currently has no int-keyed single-row lookup anywhere in the codebase (every caller does `GetAllAsync()` + in-memory `FirstOrDefault`), matching the established feature-repo-by-id convention (see `PurchaseRequestRepository`/`CalendarEventRepository`).
2. **New** `IAipRepository.GetLatestByFiscalYearAsync(int fiscalYear, ct)` — single `WHERE FiscalYear = @fy` query, replaces the `GetAllAsync()` + in-memory filter in both `GetDashboardAsync` and `BuildOfficeAipSummaryAsync`.
3. **New** `IWfpExpenditureRepository.CountActivitiesWithExpenditureAsync(int officeId, int? divisionId, int fiscalYear, ct)` — real `COUNT(DISTINCT wfp_activity_id)` scoped join. No existing method computes this.
4. **Swap** `BudgetPlanningDashboardService`**'s injected repos**: `IRepository<WfpRecord>` → `IWfpRepository` (unlocks the already-existing, already-SQL-scoped `GetFilteredAsync(aipRecordId, officeId, divisionId)`), `IRepository<Office>` → `IOfficeRepository`. `ILdipRepository.GetListAsync(officeId, status)` already exists and is properly scoped — just start calling it instead of `GetAllAsync()`.
5. **Rewrite** `GetDashboardAsync`: resolve PPDO's office id once via `GetByCodeAsync("PPDO")`; replace all 4 `GetAllAsync()` calls with the scoped equivalents from steps 1-4; **drop the** `GetSetupOverviewAsync` **call entirely** (it's deliberately fleet-wide by design per its own docstring — "how many of N offices are set up" stops being meaningful once permanently scoped to one office; do not attempt to parameterize it to one office, that's a different method shape, not in scope here).
6. **New per-division data**: for each active division under PPDO (or just `caller`'s division for Staff), **sequentially **`await` `WfpCeilingService.GetStatusAsync(officeId, divisionId, fiscalYear)` (already returns per-fund `WfpFundCeilingDto[]` — ceiling/remaining) and the new `CountActivitiesWithExpenditureAsync`. **Never** `Task.WhenAll` **over these —** `DbContext` **is not thread-safe** (CLAUDE.md, caused a prior prod 500 in `GetStatsAsync`).
7. **Thread** `caller: User` **into** `IBudgetPlanningDashboardService`**'s three method signatures** (today none take it) so the service enforces the division clamp, not just the Function's permission gate. In the Functions layer, stop discarding `caller` after `AuthorizeAsync` — pass it through. Non-`CanManageAllocation` callers get their `ByDivision[]` arrays clamped server-side to just their own division, mirroring `WfpReportFunctions.GetPreview`'s existing division-clamp pattern ([RAL-136](https://linear.app/ralphoksiprojects/issue/RAL-136/wfp-report-preview-division-scope-for-non-finance-users-finance-sees)) — never trust a client-supplied `divisionId` for scoping from a Staff caller.
8. **Fix** `BuildOfficeAipSummaryAsync`**'s two full-table scans** using the new `IOfficeRepository`/`IAipRepository` methods from steps 1-2.
9. **New DTO shape** (name TBD, e.g. `PpdoDashboardDto`) replacing the multi-office fields of `PlanningDashboardDto`: `FiscalYear`, `AvailableFiscalYears`, `LdipSummary` (PPDO only), `AipSummary` (PPDO only, FY-scoped), `Wfp.ByDivision[]` (WfpStatus, ActivitiesWithExpenditures, TotalActivities — replaces `WfpByOffice`), `Allocation.ByDivision[]` (Ceiling, Allocated, Remaining, per-fund breakdown from `WfpCeilingService.GetStatusAsync` — replaces `AllocationSetupOverviewDto`), `RecentActivity[]` (unchanged, already correctly scoped).
