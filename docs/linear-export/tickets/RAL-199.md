# RAL-199 — Auth: recover from cold-start refresh failures instead of forcing logout

## Background

Follow-up to [RAL-198](<https://linear.app/ralphoksiprojects/issue/RAL-198/auth-explain-unexpected-logout-instead-of-silently-bouncing-to-login>), which distinguished `token_superseded` from `token_expired` on a failed `POST /auth/refresh`. That ticket didn't address a third case that was already partially handled by `callWithRetry`: a **network error / timeout** on the refresh call (Azure Functions cold start ~5-20s, Azure SQL Free auto-pause resume ~20-30s) is currently treated identically to a definitive 401 — tokens are cleared and the user is bounced to `/login`, even though the refresh cookie was never proven invalid.

## Scope

**Frontend only** — no backend change needed. The refresh cookie is untouched by a network-error failure, so retrying the same `POST /auth/refresh` call (no re-entered credentials) can still succeed once the cold start resolves.

* New interstitial page `/reconnecting` — shown only when a refresh attempt fails with a network error (no HTTP response), never for a definitive 401.
  * Auto-retries the refresh call a few times with backoff, showing a "waking up the server" message.
  * Falls back to manual **Try Again** (re-attempt refresh) / **Cancel** (clear local state, go to plain `/login`) buttons if auto-retries are exhausted.
* `frontend/src/app/(portal)/layout.tsx` auth guard — on network-error exhaustion, redirect to `/reconnecting?next=<path>` instead of clearing tokens and going to `/login`. Definitive 401s keep today's [RAL-198](https://linear.app/ralphoksiprojects/issue/RAL-198/auth-explain-unexpected-logout-instead-of-silently-bouncing-to-login) behavior unchanged.
* `frontend/src/lib/api.ts` response interceptor — same classification for background API calls that 401 mid-session and then fail to silently refresh.

## Out of scope

* Any backend change — `AuthService.RefreshAsync` / `AuthFunctions.Refresh` are unchanged.
* Increasing `AccessTokenExpiryMinutes` / `RefreshTokenExpiryDays` or otherwise redesigning token lifetimes.
