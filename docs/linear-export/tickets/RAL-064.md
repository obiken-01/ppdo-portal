# RAL-64 — API: LDIP, AIP & WFP CRUD endpoints (.NET 9)

> 🌿 **Working branch:** `release/1.1.0` — all v1.1 work branches off `release/1.1.0` and PRs target `release/1.1.0` (not `main`).

## Overview

API layer for the PPDO Portal Budget Planning feature (LDIP, AIP, WFP). Part of [RAL-59](<https://linear.app/ralphoksiprojects/issue/RAL-59/budget-planning-management-feature-ldip-aip-and-wfp-web-pages>).

**v1.1 scope now includes Config endpoints** — see [RAL-70](<https://linear.app/ralphoksiprojects/issue/RAL-70/api-config-crud-endpoints-csv-uploaddownload>) for Config CRUD + CSV endpoints. This ticket covers Budget Planning endpoints only.

## Status Workflow

**Draft / Final / Archived** (per `docs/v1.1/DB_Model.md` note 9 — NOT a Submitted/Approved flow):

* **Draft** = editable
* **Final** = locked (read-only); transition via `finalize` endpoint
* **Archived** = superseded/inactive (set automatically when an amendment is finalized)
* Once Final, edits require an **admin unlock** to revert to Draft

## Budget Planning Endpoints

```
# LDIP
GET    /api/budget-planning/ldip?officeId=&fiscalYear=
POST   /api/budget-planning/ldip
PUT    /api/budget-planning/ldip/{id}
POST   /api/budget-planning/ldip/{id}/finalize       (Draft → Final)
POST   /api/budget-planning/ldip/{id}/unlock         (Final → Draft; admin only)

# AIP
GET    /api/budget-planning/aip?officeId=&fiscalYear=&sector=
POST   /api/budget-planning/aip/upload        (xlsm file upload, 4 sheets)
POST   /api/budget-planning/aip/confirm       (confirm parsed import)
GET    /api/budget-planning/aip/{id}
POST   /api/budget-planning/aip/{id}/finalize
POST   /api/budget-planning/aip/{id}/unlock           (admin only)

# WFP
GET    /api/budget-planning/wfp?aipId=&officeId=
POST   /api/budget-planning/wfp              (save full WFP payload)
PUT    /api/budget-planning/wfp/{id}
POST   /api/budget-planning/wfp/{id}/finalize
POST   /api/budget-planning/wfp/{id}/unlock           (admin only)
```

## Business Rules (backend-enforced)

* **WFP validation:** `quarterly_total` (Q1+Q2+Q3+Q4) must NOT exceed `net_appropriation` per expenditure line — reject the save with a clear validation error (`docs/v1.1/DB_Model.md` note 14)
* Finalized records reject PUT/POST modifications (409 or validation error)
* Snapshot columns (`account_number_snapshot`, `account_title_snapshot`, `funding_source_snapshot`) populated at save time
