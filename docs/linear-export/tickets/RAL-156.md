# RAL-156 — WFP entry: fund-source default, hints & per-fund allocation bars (frontend)

> Part of **v1.4.3 — Other Fund Source Ceiling & Allocation**. Child of the WFP Rework epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> **Blocked by** [RAL-154](https://linear.app/ralphoksiprojects/issue/RAL-154/fund-source-scoped-ceiling-allocation-and-wfp-check-backend) (WfpCeilingStatusDto per-fund-source breakdown).
> Working branch: `release/1.4.3`. Feature branch off `release/1.4.3`; PR targets `release/1.4.3` (NOT `main`).

## Why

When adding a WFP expenditure, the fund source is taken from the AIP activity and left blank when unresolved, with no default and no over-allocation feedback per fund. This ticket adds fund-source defaulting, live hints, and per-fund allocation bars.

## Authoritative spec

Read `docs/v1.4.3/v1.4.3_Requirements.md` FULLY — especially §5.2 (D5 default, D6 bars, D9 hints).

## Files to read before writing code

* `frontend/src/app/(portal)/budget-planning/wfp/entry/page.tsx` — `resolveDefaultFundingSourceId` (~105-120); `useCeilingStatus` (~155-210); the expenditure wizard fund-source `<Lookup>` (~546-559); sticky ceiling header (~1288-1314)
* `frontend/src/lib/allocation.ts` — `getCeilingStatus` (now returns per-fund list)
* `frontend/src/types` — `WfpCeilingStatusDto` (add the per-fund-source list)

## Steps

1. `resolveDefaultFundingSourceId` (D5): single resolvable AIP fund source → that source; blank/none → General Fund; ambiguous (comma/slash) → null (unselected). Put "blank → GF" behind a named constant (`DEFAULT_FUND_SOURCE_CODE = "GF"`) and a `FALLBACK_AMBIGUOUS_TO_DEFAULT = false` flag so option-a can be enabled later without a refactor.
2. **Hints** (D9, display-only, not persisted): in the expenditure popup's Fund Source field, show a note when (a) the value was auto-defaulted to GF because the activity had no fund source, or (b) the selected fund source differs from the activity's AIP-assigned fund source.
3. **Allocation bars** (D6): sticky header shows the GF allocation bar always, PLUS the activity's own resolved AIP fund-source bar when it is a single non-GF source (e.g. GAD → show GF + GAD), PLUS a bar for any other fund source that has ≥1 expenditure on the selected activity — driven by the per-fund `WfpCeilingStatusDto`.
4. `useCeilingStatus`: compare the pending amount against the SELECTED fund source's allocation remaining (matching the server's fund-scoped block-on-save), not a single aggregate allocation.

## Out of scope / do NOT

* Do NOT persist the hint text.
* Do NOT change the AIP-budget banner logic (still aggregate).
* Keep the save-button-disable behaviour consistent with the server check.
