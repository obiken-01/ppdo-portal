# RAL-140 — WFP entry: add "Change Project" button (before "Change activity")

> 🌿 Working branch: `release/1.4.2` (off `main`). PR targets `release/1.4.2`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14).
> 📌 Frontend-only, small.

## Why

Once an activity's expenditure list is open, the only way back up the hierarchy is "Change activity" (resets activity only) or "Done" (resets Program+Project+Activity). There's no quick way to change just the **Project** (and its activity) while keeping the Program. Add a "Change Project" button so the user can step back to project selection without fully resetting.

## Current behavior

`frontend/src/app/(portal)/budget-planning/wfp/entry/page.tsx`:

* Footer buttons (~line 1453-1460): "Change activity" (`handleChangeActivity`, ~line 1084 — clears activity only) and "Done" (`handleDone`, ~line 1090 — clears program/project/activity).

## Scope

* Add a "Change Project" button **before** "Change activity". Its handler clears the selected Project **and** Activity (keeps the Program selected), so the user lands back on the Project picker. Mirror `handleChangeActivity` but also `setSelectedProjectId(null)`.
* Order in the footer: `Change Project · Change activity · Done`.

## Out of scope

Any change to the Program/Project/Activity `Lookup` components themselves (see the separate PPA-selector display ticket).
