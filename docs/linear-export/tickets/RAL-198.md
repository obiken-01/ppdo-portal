# RAL-198 — Auth: explain unexpected logout instead of silently bouncing to /login

> Supersedes [RAL-143](https://linear.app/ralphoksiprojects/issue/RAL-143/bug-intermittent-redirect-to-login-during-normal-use) — root cause found, see below.

## Root cause (confirmed 2026-08-02)

`Users` stores a **single **`RefreshToken` / `RefreshTokenExpiry` per row ([AuthService.cs](<../backend/PPDO.Application/Services/AuthService.cs>)). Both `LoginAsync` and `RefreshAsync` overwrite it (rotation-on-use, one active token per account, not per session/device).

Sequence that ejects a still-logged-in user with zero explanation:

1. User A logs in → refresh token R1 stored in `Users` row.
2. Same account logs in elsewhere (a second person sharing the account, or A on a second device/tab) → refresh token R2 overwrites R1 in the DB.
3. A's 15-min access token expires → silent refresh (`api.ts` interceptor) sends R1 → `FindByRefreshTokenAsync` finds nothing → `AuthService.RefreshAsync` returns null → 401 → A is redirected to `/login` with no explanation.

This is the same rotation mechanism [RAL-143](https://linear.app/ralphoksiprojects/issue/RAL-143/bug-intermittent-redirect-to-login-during-normal-use) flagged as a "concurrency angle" (parallel-tab race) — but the primary real-world trigger is **two people sharing one login**, confirmed by Ralph. Org-level fix for that is "give the second person their own account" — this ticket is just about explaining the logout when it happens, not redesigning session storage to support concurrent devices per account.

## Scope

**Backend** (`AuthService.RefreshAsync`, `AuthFunctions.Refresh`):

* Distinguish and return a reason on 401 instead of a bare 401:
  * `token_superseded` — a refresh token was presented but the row's current token doesn't match (someone else logged in / refreshed after this token was issued).
  * `token_expired` — token matched but past `RefreshTokenExpiry` (natural 7-day expiry).
  * No cookie present at all → plain unauthenticated, no reason needed (normal logged-out state).

**Frontend** (`api.ts` interceptor, portal auth guard in `layout.tsx`, `/login` page):

* On failed silent refresh, carry the reason to the login page (e.g. redirect query param) and show a banner:
  * `token_superseded` → "You were signed out because someone signed into this account from another device or browser. If you both need access at the same time, ask an admin for a separate account."
  * `token_expired` → "Your session expired — please sign in again." (current generic behavior)

## Out of scope

* Multi-session support (one refresh token per device) — not requested; the org resolution for shared-account conflicts is separate accounts, not concurrent sessions.
* Redesigning the auth/session model.
