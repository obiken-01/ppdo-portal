# RAL-125 — WFP entry UI: procurement line-item entry (price index + presets)

> 🌿 **Working branch: **`release/1.4.0`. PRs target it, **not **`main`.
> 📌 Read the epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14) first, then `docs/v1.4/WFP_Rework_Requirements_Draft.md` §5.2 FULLY. Depends on [RAL-118](https://linear.app/ralphoksiprojects/issue/RAL-118/config-price-index-page-procurement-item-catalogue) (Price Index), [RAL-119](https://linear.app/ralphoksiprojects/issue/RAL-119/config-procurement-presets-reusable-line-item-templates-per-account) (Procurement Presets), and the wizard shell ([RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14)'s #9) — all three must merge first.

## Why

Procurement expenditures compute their Total Appropriation **bottom-up from line items** (item name × qty × price) instead of an estimated lump sum, per the demo — so the number the WFP form shows is a real computation, not a guess.

## Scope

* A per-period item table: **Item name · Unit · Qty · Unit price · Line total (computed)**.
* **Item search**: typeahead against [RAL-118](https://linear.app/ralphoksiprojects/issue/RAL-118/config-price-index-page-procurement-item-catalogue)'s price index (by name); picking a result fills name/unit/price. Price is **snapshotted** onto the WFP item at that moment — later price-index edits must never retroactively change a saved line (verify this against [RAL-118](https://linear.app/ralphoksiprojects/issue/RAL-118/config-price-index-page-procurement-item-catalogue)/[RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation)'s snapshot semantics).
* **Presets**: "Load preset" (filtered to the current account, from [RAL-119](https://linear.app/ralphoksiprojects/issue/RAL-119/config-procurement-presets-reusable-line-item-templates-per-account)) copies its items in as a starting point (still editable, still snapshot semantics); "Save as preset" writes a new preset via [RAL-119](https://linear.app/ralphoksiprojects/issue/RAL-119/config-procurement-presets-reusable-line-item-templates-per-account)'s quick-save endpoint.
* **Carry-forward across periods** (§5.2, per the demo): the same item set persists as the user steps between periods; qty is editable per period, items available via "copy previous period" / "apply to all periods" (same explicit-action rule as ticket #10's frequency grid — no silent auto-persistence).
* Live per-period total = `Σ(qty × price)`; overall totals strip same as ticket #10 (reads [RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation)'s computed values).
* **"Combined" nature**: still undefined (open question, epic-level). Build this ticket for the Procurement and Non-Procurement branches only; if the wizard routes a Combined-nature expenditure here, show a simple placeholder ("Combined entry — pending definition") rather than guessing at behavior.

## Acceptance Criteria

- [ ] Item search returns price-index matches with name/unit/price/`price_updated_at`; picking one snapshots values into the row
- [ ] Snapshotted item values do NOT change if the underlying price-index item is edited afterward
- [ ] "Load preset" copies items (not a live reference); "Save as preset" round-trips through [RAL-119](https://linear.app/ralphoksiprojects/issue/RAL-119/config-procurement-presets-reusable-line-item-templates-per-account)'s endpoint
- [ ] Per-period item carry-forward is an explicit action, matching ticket #10's UX rule
- [ ] Live per-period total = Σ(qty × price), matches what [RAL-120](https://linear.app/ralphoksiprojects/issue/RAL-120/wfp-expenditure-schema-rework-periods-procurement-items-computation)'s backend computes
