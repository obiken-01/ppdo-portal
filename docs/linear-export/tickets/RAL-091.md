# RAL-91 — Perf: optimize login page seal/logo PNGs (184 KB → WebP/next-image)

## Context

Low-severity finding from the v1.1.0 audit (2026-06-22). The login page (the first thing every user sees) serves two raw PNGs:

* `frontend/public/images/Ph_seal_occidental_mindoro.png` — ~98 KB
* `frontend/public/images/Bagong_Pilipinas_logo.png` — ~86 KB

~184 KB of unoptimized image weight on the highest-traffic public page. Login still scores 98 on Lighthouse, so this is polish, not urgent — but it's a cheap win and improves the first impression on slow connections.

> 🌿 **Working branch:** create feature branch off `hotfix/1.1.1` — PR targets `hotfix/1.1.1` (NOT main)

### Approach

Use the Next.js `<Image>` component, which auto-serves WebP/AVIF, lazy-loads, and sets explicit dimensions (also avoids any layout shift). Confirm how the images are currently referenced in `(public)/login/page.tsx` — if they're plain `<img>` tags, swap to `next/image` with explicit `width`/`height`. (`ppdo-logo-placeholder.png` can be migrated too if it's on the login/landing path.)

> Verify `next.config.js` allows the import path / has image optimization enabled (it is on by default for local `public/` images). No remote-domain config needed since these are local assets.

## Acceptance Criteria

- [ ] Login seal + logo served as optimized/responsive images (WebP/AVIF via `next/image`)
- [ ] Total image bytes on `/login` drop materially from ~184 KB
- [ ] Images have explicit dimensions — no layout shift introduced
- [ ] Login page still renders correctly at desktop + mobile widths
- [ ] tsc + `npm run build` pass
