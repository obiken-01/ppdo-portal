# RAL-84 — Backend: calendar event approval workflow (service + endpoints)

## Context

Part of v1.1.1 — Calendar Event Approval feature. [RAL-82](https://linear.app/ralphoksiprojects/issue/RAL-82/db-add-approval-fields-to-calendarevents) added the DB columns. This ticket wires up the business logic in `DashboardService` and adds three new API endpoints for the approval workflow.

## Scope

### Application layer changes (`PPDO.Application`)

Update `IDashboardService` and `DashboardService`:

`CreateEventAsync` **(changed):**

* If `EventType == "Office"` AND caller is NOT Admin/SuperAdmin → set `Status = Pending`
* If `EventType == "Office"` AND caller IS Admin/SuperAdmin → set `Status = Approved`
* Personal events always skip approval (no status change needed — they're private)

`GetEventsAsync` **(changed):**

* Return Approved Office events to all authenticated users (existing behaviour)
* ALSO return the caller's own Pending and Rejected Office events (creator can see their own pending/rejected events)
* Personal events: unchanged (only returned to creator)

**ADD **`GetPendingEventsAsync(caller, ct)`**:**

* Admin/SuperAdmin only → returns `ServiceResult<List<PendingCalendarEventDto>>`
* Returns all `Status = Pending` Office events, ordered by `CreatedAt ASC`
* Non-admin caller → `ServiceResult.Forbidden`

**ADD **`ReviewEventAsync(caller, id, dto, ct)`**:**

* Admin/SuperAdmin only
* If `dto.Approved == true` → set `Status = Approved`, clear RejectionReason
* If `dto.Approved == false` → set `Status = Rejected`, set `RejectionReason = dto.RejectionReason`; reason is required if rejecting
* Set `ReviewedById = caller.Id`, `ReviewedAt = DateTime.UtcNow`
* Returns updated `CalendarEventDto`

**ADD **`DeleteEventAsync(caller, id, ct)`**:**

* Creator can delete their own event (any status)
* Admin/SuperAdmin can delete any event
* Others → `ServiceResult.Forbidden`

### New/updated DTOs (`PPDO.Application/DTOs/Dashboard/`)

Update `CalendarEventDto`: add `Status` (`CalendarEventStatus`) and `RejectionReason` (`string?`)

ADD `ReviewCalendarEventDto`:

```csharp
public sealed record ReviewCalendarEventDto(bool Approved, string? RejectionReason);
```

ADD `PendingCalendarEventDto`:

```csharp
public sealed record PendingCalendarEventDto(
    Guid Id, string Title, string? Description,
    DateTime StartDate, DateTime? EndDate, bool IsAllDay,
    string CreatedByName, DateTime CreatedAt);
```

### Functions changes (`DashboardFunctions.cs`)

ADD three endpoints:

| Method | Route | Auth | Notes |
| -- | -- | -- | -- |
| GET | `/api/dashboard/events/pending` | JWT, Admin/SuperAdmin | Returns `List<PendingCalendarEventDto>` |
| PUT | `/api/dashboard/events/{id:guid}/review` | JWT, Admin/SuperAdmin | Body: `ReviewCalendarEventDto` |
| DELETE | `/api/dashboard/events/{id:guid}` | JWT | Creator or Admin/SuperAdmin |

## TDD Requirements

Write tests BEFORE implementing. Cover:

* `CreateEventAsync` — Office event by Staff → `Pending`; Office event by Admin → `Approved`; Personal event by Staff → no status change
* `GetEventsAsync` — Approved events visible to all; creator's own Pending/Rejected events returned; another user's Pending not returned
* `GetPendingEventsAsync` — Admin sees all Pending; Staff → Forbidden
* `ReviewEventAsync` — Approve sets correct fields; Reject requires reason; non-admin → Forbidden; NotFound for missing id
* `DeleteEventAsync` — Creator deletes own; Admin deletes any; other user → Forbidden
