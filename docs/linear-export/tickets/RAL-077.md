# RAL-77 — API: Audit logging for budget planning + config records

> 🌿 **Working branch:** `release/1.1.0` — all v1.1 work branches off `release/1.1.0` and PRs target `release/1.1.0` (not `main`).

## Overview

Implement application-level audit logging that writes to the `audit_log` table for all v1.1 budget planning and config entities. [RAL-67](<https://linear.app/ralphoksiprojects/issue/RAL-67/db-budget-planning-schema-v2-ldip-aip-wfp-config-tables>) creates the table; this ticket makes the application actually write to it.

This fulfills the v1.1 requirement: *"History tracking: log all changes to LDIP, AIP, and WFP records (who changed what and when)"* (`docs/v1.1/AIP_WFP_Import_Findings.md` §2, Confirmed Design Decision #8).

## Reference

* `docs/v1.1/DB_Model.md` section 5 — `audit_log` table schema
* `docs/v1.1/AIP_WFP_Import_Findings.md` — design decision #8

## Scope

Log CREATE / UPDATE / DELETE actions for:

* `ldip_records`
* `aip_records` (+ child tables on import confirm — one CREATE entry per record is acceptable, or a single summarized entry per import)
* `wfp_records`, `wfp_expenditure_lines`
* Config tables: `accounts`, `offices`, `funding_sources` (including soft-delete/deactivate)
* Status transitions (finalize / unlock) — log as UPDATE with old/new status

Each entry: `table_name, record_id, action, changed_by, changed_at, old_values (JSON), new_values (JSON of changed fields only)`.

## Design

* Implement as a reusable `IAuditService` in the Application layer, called from the budget planning and config services — not a DB trigger
* JSON snapshots should contain only changed fields (not full row dumps) to keep the table small
* `changed_by` from `CurrentUserService`

## Testing (TDD)

Write failing xUnit tests first. Cover: entry written on create/update/soft-delete, old/new values contain only changed fields, changed_by populated.

## Acceptance Criteria

- [ ] Creating, updating, and deactivating a config record writes an audit entry
- [ ] Saving a WFP writes audit entries for changed expenditure lines
- [ ] Finalize/unlock transitions are logged with old/new status
- [ ] AIP import confirm produces audit entries
- [ ] Unit tests cover the audit service
