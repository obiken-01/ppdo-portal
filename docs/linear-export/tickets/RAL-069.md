# RAL-69 — DB: Config tables migration (Accounts, Offices, Funding Sources)

## Overview

EF Core migration to add the three Configuration tables.

> **Note**: If [RAL-67](<https://linear.app/ralphoksiprojects/issue/RAL-67/db-budget-planning-schema-v2-ldip-aip-wfp-config-tables>) (Budget Planning schema v2) is implemented first and covers these config tables, this ticket is satisfied — verify and close rather than duplicating the migration.

> **Decision (2026-06-10): NO seed migration.** Seed data is loaded manually by the user through each config page's CSV Upload feature once [RAL-70](https://linear.app/ralphoksiprojects/issue/RAL-70/api-config-crud-endpoints-csv-uploaddownload)/72/73/74 are live. The seed CSVs stay outside the repo.

## Schema

```
accounts
  account_number  nvarchar(20) UNIQUE NOT NULL
  account_title   nvarchar(300) NOT NULL
  normal_balance  nvarchar(10) NULL
  description     nvarchar(MAX) NULL
  is_active       bit NOT NULL DEFAULT 1
  created_at/updated_at DATETIME2

offices
  office_code     nvarchar(20) UNIQUE NOT NULL
  office_name     nvarchar(200) NOT NULL
  is_active       bit NOT NULL DEFAULT 1
  created_at/updated_at DATETIME2

funding_sources
  code            nvarchar(20) UNIQUE NOT NULL
  name            nvarchar(100) NOT NULL
  description     nvarchar(MAX) NULL
  is_active       bit NOT NULL DEFAULT 1
  created_at/updated_at DATETIME2
```

> Config tables use `is_active` for soft delete only — no `IsDeleted` column. See [RAL-67](<https://linear.app/ralphoksiprojects/issue/RAL-67/db-budget-planning-schema-v2-ldip-aip-wfp-config-tables>) / `docs/v1.1/DB_Model.md` for the authoritative schema.
