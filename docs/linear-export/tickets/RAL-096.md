# RAL-96 — perf(dashboard): eliminate holiday HTTP calls and calendar spinner on return visits

## Background

Reported 2026-06-23. Two separate but related symptoms observed on the live `/dashboard` page:

1. **Calendar slow on first load** — intermittently noticeable after cold starts; root cause traced to `NagerHolidayProvider` always calling Nager.Date (`https://date.nager.at/api/v3/PublicHolidays/{year}/PH`) even for 2026/2027 which already have complete static data in code.
2. **Calendar spinner on every return visit** — reproducible: log in → go to another page → return to dashboard → spinner appears again. Root cause: Next.js App Router unmounts `DashboardPage` on navigation, resetting all React state including `eventsLoading = true`, triggering a fresh fetch on every mount.

Lighthouse findings that informed this work:

* Speed Index 3.2s (poor)
* LCP render delay 5,864ms
* `auth/refresh` preflight 1,000ms + 1,590ms actual (largest bottleneck, separate ticket)
* `dashboard/events` 728ms actual

---

## Fixes

### 1. `NagerHolidayProvider.cs` — static-first for known years

Added `HasStaticData(year)` private method (`year is 2026 or 2027`). The provider now checks this before deciding whether to call Nager.Date:

```csharp
IReadOnlyList<CalendarEventDto> result = HasStaticData(year)
    ? GetStaticFallback(year)
    : await FetchFromNagerAsync(year, cancellationToken) ?? [];
```

Previously: always `await FetchFromNagerAsync() ?? GetStaticFallback(year)` — external HTTP on every cold start for current years.

### 2. `Program.cs` — 3-second HttpClient timeout

```csharp
services.AddHttpClient<IHolidayProvider, NagerHolidayProvider>(c =>
    c.Timeout = TimeSpan.FromSeconds(3));
```

Previously: default 100-second timeout. A slow Nager.Date response would stall `dashboard/events` for up to 100s.

### 3. `dashboard/page.tsx` — module-level SPA events cache

```typescript
// Outside component — survives Next.js route changes
const eventsCache = new Map<string, CalendarEventResponse[]>();
```

* `events` state initialises from cache on mount: `useState(() => eventsCache.get(initKey) ?? [])`
* `eventsLoading` starts `false` if cache hit: `useState(() => !eventsCache.has(initKey))`
* `fetchEvents` shows cached data instantly on return visits, fires a silent background refetch, spinner only for true first load
