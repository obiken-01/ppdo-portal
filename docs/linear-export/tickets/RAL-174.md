# RAL-174 — Config: Audit Log page (SuperAdmin-only, feature-flagged)

> 🌿 Branch `feature/v1.4.9-audit-log-page` off `release/1.4.7` (depends on [RAL-172](https://linear.app/ralphoksiprojects/issue/RAL-172/recent-activity-timestamps-display-8-hours-behind-manila-time-backend)'s `AuditLog.RecordGuid` column). PR [obiken-01/ppdo-portal#165](https://linear.app/ralphoksiprojects/review/featconfig-add-audit-log-page-superadmin-only-feature-flagged-a097fb3e5c17) → `release/1.4.7`, NOT `main`. Child of epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14) (bundled for release-train convenience — not epic-relevant, this is a general Config feature).
> 📌 Backend + frontend, medium-large.
> Requested by Ralph 2026-07-20: "lets create a new page under configuration... only system admin can access this... a feature flag tag too just in case we let other users view the page... it will display all audit log in a table. with filter and lets introduce pagination... descriptive description of the action... timestamp, feature or table name, action, description, username."

## Why

`AuditLog` ([RAL-77](https://linear.app/ralphoksiprojects/issue/RAL-77/api-audit-logging-for-budget-planning-config-records)) already captured every CREATE/UPDATE/DELETE across Config and Budget Planning, but the only UI surfacing it was the Budget Planning Dashboard's "Recent Activity" panel — top-10, no filtering, no pagination, and (before this ticket) no coverage of User Management at all.

## What shipped

**Backend**

* `FeatureFlags.AuditLogPageEnabled` (`backend/PPDO.Application/Common/FeatureFlags.cs`) gates `PermissionService.CanViewAuditLogAsync` — SuperAdmin-only for now, `static readonly` (not `const`) so flipping the flag never produces an "unreachable code" warning at call sites. Flip the flag or extend that one method's role check to open access to other roles later — no Function/frontend change needed either way.
* `AuditLog.RecordId` (`backend/PPDO.Domain/Entities/AuditLog.cs`) is now `int?`, and a new nullable `RecordGuid` (`Guid?`) column was added (migration `AddAuditLogRecordGuid`) — the table previously only supported int-keyed audited tables, and `users` has a Guid PK. New `IAuditService.LogAsync(string, Guid, ...)` overload alongside the existing `int` one.
* `UserService` now calls `_audit.LogAsync` on Create/Update/SetPermissions/ResetPassword/Deactivate/Reactivate. Snapshots deliberately exclude `PasswordHash`/`RefreshToken`/`RefreshTokenExpiry`; `ResetPasswordAsync` logs only a `{ PasswordReset: true }` marker, never any password material.
* New `AuditDescriptionBuilder` (`backend/PPDO.Application/Common/AuditDescriptionBuilder.cs`) — table-agnostic: builds a human-readable, possibly multi-line description by diffing a row's `OldValues`/`NewValues` JSON (`"- Full Name: Jane Doe → Jane D. Smith"` style, one line per changed field). No changes needed here when a new service starts calling `LogAsync` — it works purely off whatever fields the caller logged.
* New `AuditRepository.GetPagedAsync` (server-side filter by table/action/actor-search/date-range + `Skip`/`Take` + total count — `audit_log` has no natural size cap, per `docs/PERFORMANCE_GUIDELINES.md`) and `GetDistinctTableNamesAsync` (drives the table filter dropdown without a hardcoded list that could drift).
* New `IAuditLogService`/`AuditLogService` and `AuditLogFunctions` — `GET /config/audit-log?page=&pageSize=&tableName=&action=&actor=&from=&to=`, `GET /config/audit-log/tables`.

**Frontend**

* New `/config/audit-log` page: filters (table dropdown sourced from real distinct values, action dropdown, username free-text search, From/To date range), server-side pagination (50/page), columns for Timestamp (Manila time, `toLocaleString("en-PH", {timeZone:"Asia/Manila"})`), Feature/Table, Record (`#id` or shortened `#guid`), Action (color-coded badge), Description (`whitespace-pre-line` for the multi-line diff text), Username.
* Extended the shared `DataTable` component with an opt-in `serverPagination` prop — `rows` is assumed to already be the current page; the footer's row count and Prev/Next are driven from `{ page, pageSize, totalCount, onPageChange }` instead of `rows.length`/internal page state. Purely additive — takes precedence over `pageSize` only when supplied, so the ~12 existing pages using client-side `pageSize` pagination are byte-for-byte unaffected. This is also the exact primitive Inventory's list pages will need whenever their own documented pagination gap (`PERFORMANCE_GUIDELINES.md`) gets tackled.
* Sidebar link (`Configuration → Audit Log`) gated on `me.role === "SuperAdmin"`, as its own independent condition alongside the existing `showConfig`/`showManageUsers` link groups.
* Budget Planning Dashboard's Recent Activity widget (`budget-planning/page.tsx`) updated with a `recordLabel()` helper to render a shortened Guid (`#63f6c07b`) when `recordId` is null, since User Management audit entries now surface there too, mixed in with WFP/AIP/Config changes (unchanged existing behavior — `AuditRepository.GetRecentAsync` was never table-filtered).
* **Deliberately no Config Dashboard tile** — Ralph's explicit call after the first pass added one; sidebar link only.

## Out of scope (flagged for later, not blocking)

* No per-user/division override for Audit Log access (SuperAdmin-only, hardcoded role check inside the feature-flagged permission method) — add one to `PermissionService.CanViewAuditLogAsync` if finer-grained access is ever needed.
* Self-service actions (`UpdateOwnProfileAsync`, `ChangePasswordAsync` on the `/account` page) are NOT audited — this ticket scoped strictly to the admin-facing User Management operations (Create/Update/SetPermissions/ResetPassword/Deactivate/Reactivate), matching the "User Management" feature naming precisely.
* Other unaudited feature areas identified in an earlier pass this session (Inventory: PR/Delivery/Distribution/ItemMaster; Announcements; Resource Links; Dashboard/Calendar events; Auth login/logout) remain unaudited — out of scope for this ticket, which was User Management only.
