# RAL-236 — Distribution: "All Distributions for {StockNo}" table shows numeric Division ID instead of division name

**Reported by Ralph, screenshot on the Distribution page.** The "ALL DISTRIBUTIONS FOR {StockNo}" table (Distribution item-detail view, e.g. `OSE-2930536960`) renders a raw numeric ID in the DIVISION column pill (e.g. `5`) instead of the division's display name.

## Root cause (confirmed by code read)

`ExistingDistributionDto.Division` (`backend/PPDO.Application/DTOs/Distribution/ItemDistributionSummaryDto.cs:38-45`) is declared `string` but is populated from the raw `DivisionId` int, not a name lookup — two call sites in `DistributionService.GetItemSummaryAsync` (`backend/PPDO.Application/Services/DistributionService.cs`):

* Line ~131 (delivery-batch distributions): `d.DivisionId.ToString()`
* Line ~159 (warehouse-count pool distributions): same pattern

The frontend (`frontend/src/app/(portal)/inventory/distribution/page.tsx:681-685`) just renders `{d.division}` verbatim inside the green pill — it's a straight pass-through of whatever the API sends, so it displays whatever `Division` field the DTO carries. `ExistingDistributionResponse` in `frontend/src/types/inventory.ts:371-379` even claims `division: string` with a comment "Mirrors ExistingDistributionDto", masking that the value is actually a stringified ID, not a name.

## Why this is isolated, not systemic

Other services building near-identical distribution rows resolve the name correctly — including a **sibling method in the same file**:

* `DistributionService.AllocateAsync` (~line 215-328, same file) builds a `Dictionary<string, Division>` lookup and returns `division.Name`.
* `PRReportService.cs:200` — `Division: dist.Division?.Name ?? ""` (feeds the PR Report's distribution table, which displays correctly).
* `PurchaseRequestService.cs:979,986` — `pr.Division?.Name ?? ""`.
* `DeliveryService.cs:225-229` — builds a `divisionIdByName` dictionary for the reverse mapping.

So only `DistributionService.GetItemSummaryAsync`'s two `ExistingDistributionDto` construction sites skipped the lookup.

## Fix

Mirror the existing `divisionByName`/`.Name` pattern already used in `AllocateAsync` (same file) at the two `ExistingDistributionDto` construction sites (~line 131 and ~line 159) in `GetItemSummaryAsync` — resolve `DivisionId` → `Division.Name` before building the DTO, instead of `d.DivisionId.ToString()`. No schema/migration change needed. Update the `ExistingDistributionResponse` TS comment once fixed so it no longer misleadingly claims the field already mirrors the DTO correctly.

## Out of scope

No other tables are affected — PR Report, PR List, and the Allocate flow already show correct division names.
