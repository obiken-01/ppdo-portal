# RAL-126 — WFP: Program function band (CORE/STRATEGIC/SUPPORT) + Activity "CREATION" flag (Q1/Q2)

> 🌿 **Working branch: **`release/1.4.0`. PR targets it, **not **`main`.
> 📌 Resolves two of the epic [RAL-116](https://linear.app/ralphoksiprojects/issue/RAL-116/wfp-rework-epic-v14) "deliberately NOT started" blockers (function bands + "CREATION"), now that Ralph answered them (2026-07-10 — Open Questions Q1 & Q2 in `WFP_Rework_Open_Questions_UPDATED.xlsx`).

## Why

The WFP report generator (a later, not-yet-built ticket) needs two facts captured **during data entry now**, so real WFP data entered this cycle doesn't need retroactive backfilling later:

* **Q1 — Function band:** each **program** is `CORE` / `STRATEGIC` / `SUPPORT`. Chosen by the user at program level; drives the report's section layout.
* **Q2 — "…-CREATION" flag:** a per-**activity** boolean, default off. Marks activities whose PS expenditures roll up under the `TOTAL - … - CREATION` summary rows (General-Fund, Personal-Services, position-creation activities only). Per Ralph: a checkbox at activity level, unchecked by default.

Both are captured inline in the **WFP entry wizard's context picker** (not a separate AIP editor — the AIP detail page stays read-only). Storage lives on `AipProgram` / `AipActivity` (structurally correct — function band is a program attribute, creation is an activity attribute, independent of any one WFP record).

## Scope (implemented)

**Backend**

* `AipProgram.FunctionBand` (nullable string) + `AipActivity.IsCreation` (bool, default false) — snake_case columns `function_band` / `is_creation`, migration `AddAipProgramFunctionBandAndActivityIsCreation`.
* `AipFunctionBand` constants class (`CORE`/`STRATEGIC`/`SUPPORT`) + case-insensitive canonicalization in `AipService` (mirrors `AccountService.TryCanonicalizeNature`; null/empty clears).
* Two `PUT` endpoints, gated by `CanAccessBudgetPlanning` (not the stricter upload gate): `budget-planning/aip/programs/{id}/function-band`, `budget-planning/aip/activities/{id}/is-creation`.
* New fields threaded through `AipProgramDto`/`AipActivityDto` + the slim summary DTOs; new `IAipRepository.GetProgramByIdAsync`.

**Frontend**

* Function Band `<select>` + "…-CREATION" checkbox rendered inline under the wizard's Program/Project/Activity picker, appearing once the relevant node is selected. Optimistic local patch of `aipDetail`, revert + toast on failure.

**Tests**: 9 new `AipServiceTests` cases (valid/canonicalize/clear/invalid/not-found for function band; true/false/not-found for creation). Full suite green (595).
